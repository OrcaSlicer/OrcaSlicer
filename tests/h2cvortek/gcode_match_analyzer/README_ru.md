# G-code Match & Correctness Analyzer для принтеров H2C

Этот инструмент предназначен для анализа качества нарезки G-кода для принтеров Bambu Lab H2C и сравнения нарезок между Bambu Studio и OrcaSlicer.

## Возможности

1. **Анализ одного файла (корректность)**:
   - Проверка геометрии слоев (Z-высоты).
   - Проверка ретрактов (длина `M620.11 O1 T18` для PLA и `T14` для PETG-CF).
   - Проверка корректности адресации хотэндов при предохлаждении (охлаждение неактивного хотэнда `M104 T[parked]` вместо работающего).
   - Проверка дублирования и конфликтов температурных команд `M104` в пределах одной смены.
   - Контроль температурного пола предохлаждения (запрет остывания ниже 150°C).
   - Подсчет объема продувки (flushing length) по каждому инструменту на основе команд `M620.10`.
   - Проверка ретрактов смены экструдеров (`M620.11 K1 R10` для защиты от застревания в датчике FTS).
   - Проверка баланса команд планировщика температуры (`M632`/`M633`).
   - Проверка компенсации вытекания PETG на башне (`filament_tower_interface_pre_extrusion_length`).

2. **Сравнение двух файлов (BBL vs OrcaSlicer)**:
   - Автоматическое определение взаимного переключения/маппинга хотэндов (например, T0 $\leftrightarrow$ T4).
   - Сравнение распределения G-код команд (G1, G2, G3, M104, M204, M73 и т.д.).
   - Послойное сопоставление Z-высот и количества строк G-кода.
   - Сравнение распределения расхода филамента по типам элементов (Feature Extrusion Profile).
   - Сравнение суммарного объема продувки (flushing volume) по логически сопоставленным парам инструментов.
   - Детальный построчный анализ логически выровненных блоков смены филамента (Toolchange).

## Использование

Скрипт написан на чистом Python 3 и не требует внешних зависимостей.

### 1. Вывод в консоль (По умолчанию)

Если не передать параметр `--to-file`, отчет выводится прямо в стандартный поток вывода (консоль):

```bash
# Анализ ошибок в одном файле
python3 analyzer.py -f1 /path/to/my_slice.gcode

# Сравнение двух нарезок
python3 analyzer.py -f1 /path/to/10bbl.gcode -f2 /path/to/16orca.gcode
```

### 2. Запись отчетов в файлы (`--to-file`)

Если указан флаг `--to-file`, отчеты сохраняются в файлы (текстовый `.txt` для чтения человеком и структурированный `.json` для анализа агентом):

```bash
# Запись отчета по одному файлу
python3 analyzer.py -f1 /path/to/my_slice.gcode --to-file

# Запись отчета по сравнению
python3 analyzer.py -f1 /path/to/10bbl.gcode -f2 /path/to/16orca.gcode --to-file
```

### Параметры запуска
* `-f1` / `--file1`: Путь к первому файлу G-кода (обязательный).
* `-f2` / `--file2`: Путь ко второму файлу G-кода для сравнения (необязательный).
* `--to-file`: Флаг для записи отчетов в файлы вместо вывода в консоль (необязательный).
* `-o` / `--output`: Префикс путей выходных файлов (необязательный, применяется только при `--to-file`, по умолчанию сохраняет на Рабочий стол или в текущую директорию).
