# 关键色保留、工程耗材试色与历史背景展示

## 范围

用户批准下一版“关键色保留＋实际六色即时对照”，以及去掉历史图棋盘格的展示处理。基于 `codex/continue` 的已有工作树继续实现，保留所有原始模型和图片；本轮不实现正式工程配色应用、CMYK 配方或试切，不联系同事、不调用项目收费生成服务。

## 实现与边界

- `ModelPreviewPalette.hpp` 增加固定目标颜色和色相保护。后者按 Oklab 色相分组，只保护有最低面积支持的彩色，给主色／中性色留位置；并非人脸或衣服语义分割。自动建议最多六色，可关闭色相保护回到面积聚类。
- `ModelPreviewColorControls.hpp` 提供 1–6 色、自动建议／当前工程耗材／手动试色、目标颜色保留、颜色编辑、重置和原色对照。锁色防止重聚类漂移。手动编辑保留编辑前的颜色分组，将目标颜色替换给同一组，避免新目标因最近邻重分配而完全不生效；该颜色组可能跨多个空间区域。
- 工程耗材读取与原生纹理导入相同的 `PresetBundle::project_config`，保留原槽位身份，排除 `filament_is_mixed` 虚拟混色；不会把六个逻辑颜色都声称为六种实体材料。未配置、无有效色值或超过六种实体色时提示，并保持原色；不截断、不改工程、不拦截导入。预览按钮和可见页面空闲检查会检测设备／耗材变化，恢复原色并要求重新对照。
- 直方图随 CPU 准备保留，修改试色只重算小直方图和更新 shader uniforms，不重复加载 OBJ／上传几何。页面往返保留试色；换模型／美颜版本清除试色，缓存命中也恢复新模型的自动建议。
- 导入仍使用原色文件。本轮没有新增第二套正式匹配或 CMYK 配方。原生应用、耗材标定和空间／层次叠色保持交接文档的职责边界。

## 背景处理

历史 AI PNG 本身是 RGB 棋盘格，不能只换界面底色消除。本轮通过内置 image_gen 生成独立展示副本，未调用项目 provider。副本无棋盘格，但生成式编辑轻微重绘了脸部／衣物／腕表细节，所以界面明确标为“展示修整”，提供“查看原始 AI 图”复选框，原始 AI 文件仍用于所有生成、分析、版本保存和导入衔接。

`ModelImageDisplayCopy.hpp` 只加载原图旁的 `.display.png` 可选展示文件；原图时间更新后，旧副本不再采用。模型库缩略图使用同一副本并带明确说明。展示副本当前只为这份历史样例制作，不宣称批量处理所有历史图片。原有界面透明图底层棋盘格绘制也已改为纯中灰底。

编辑副本与提示词记录在 `.tmp/ux-performance-20260909/428a0fe0-display-solid-gray-edit.md`。原始 PNG SHA256 为 `bd2d70ef1acb590990ff81753c183d69820d01c228218d1a0de4e2e7de601e8e`，展示副本为 `d3e623351872f55015fd5d9e5c7a00219a7ce2d4a82fb8f090e94ac4320061e4`。它不能作为人物相似度或颜色保真的原始基准。

## 验证

- 最终定向 C++ 测试已通过：8 用例、187 断言，随机顺序种子 137831541，日志 `protected-six-color-tests-final.log`。覆盖已有色彩转换／面积权重／数量，以及灰阶中少数彩色保护、锁色稳定、无效锁色与小通道数，并补充真实模型发现的低色度深绿和少量强色回归。
- 集成检查仍有四项既有错误：`release/test_verify_package_contents.py:39` 与 `tools/ai/test_diagnostic_failure_flow.py:106` 的模拟凭据字面量；缺失历史 `codex/model-generation`、`codex/smart-slicing` 引用。没有削弱检查或绕过受阻的旧工作区比较。
