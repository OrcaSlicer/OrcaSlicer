# RGB 设计图预检误拦修复与主窗口验证

日期：2026-09-09。测试对象是 `codex/continue` 的当前未提交工作树，基于 `ad4f74b97ae89d3cd9371d0c3214cd31f3b6269f`，不是该提交单独的结果。

## 问题与根因

用户在主窗口生成完整的浅色衣服半身像后，出现“图片包含多个断开的主体或碎片”，生成 3D 按钮禁用。已在实际主窗口确认报错，并对该任务保存的设计图离线复现。

该文件是 **1024 × 1536 的不透明 RGB PNG**，棋盘格是图像内的像素，并非真正的透明背景。原检查使用四角颜色和固定色距估计前景，将白衣与背景混淆，得到 4 个有意义颜色分量，最大分量占比 0.407284，因此错误地硬判 `fragmented_subject`。颜色分量不等于主体几何分量。

## 修复

- `tools/ai/model_input_image_quality.py`：真实 alpha 轮廓保留碎片硬拦；RGB 色差分割的碎片结论改为 `foreground_segmentation_uncertain` 提醒，并记录 `foreground_mask_source`。没有调低分量比例阈值，也没有把各分量强行连接。
- `tools/ai/orca_ai_sidecar.py`：恢复待确认任务时，两套质量检查通过后更新旧错误文案；保留其他失败及多视图重试阶段。
- `src/slic3r/GUI/ModelGenerationPanel.cpp`：在主窗口明确显示轮廓检查不确定的提醒，要求用户查看完整主体和背景；不覆盖真正的质量阻塞。
- 增加合成图回归及真实 HTTP 路由回归，覆盖低对比度人像、真实透明轮廓、恢复、明确提交和重复请求。

实际设计图的检查结果由阻塞变为可继续确认，仍保留贴边及分割不确定提醒。原图和设计图没有重绘、补色、量化或替换；设计图 SHA-256 保持 `bd2d70ef1acb590990ff81753c183d69820d01c228218d1a0de4e2e7de601e8e`。

## 边界与剩余风险

不透明 RGB 的真实双主体也只能得到不确定提醒；本次没有新增可靠分割模型，不能声称证明了连通性。烘焙棋盘格仍保留在供应商返回的原图中，可能影响实际 3D 生成，这个后续效果没有验证。本轮不通过自动抠图、重绘或重试收费服务改变用户已确认的作品。

本次实际 GUI 证据只覆盖当前图片确认、恢复和页面切换。生成后导入、三维修整完整旅程、真实切片/打印及安装包验收仍需继续；[发布验收报告](2026-09-09-release-readiness.md)中的三个修整问题、旧 Python 失败、集成与打包阻塞没有因此解决。
