## 优先问题

### 1. P1：取消导入后仍显示“导入模型 98%”

**证据：实际界面 + 当前源码。** 左上步骤停在“4 导入”，绿色进度条 98%；底部同时显示“已取消导入”“模型仍保留在本地”。用户无法判断是否还有后台任务。

源码在 `ModelGenerationPanel.cpp:2568` 设置 98%，在 `2606` 的取消分支只更新提示、恢复按钮，没有恢复进度阶段。其他导入失败分支也沿用该进度。

建议：取消后统一显示“待导入”，隐藏进行中进度；主按钮使用“重新导入”。模型、原图、设计图继续保留。验证时同时覆盖取消颜色匹配、导入失败和再次导入。

### 2. P1：空板检查的完成状态不真实，错误没有下一步入口

**证据：实际操作 + 当前源码。** 智能切片尚未检查就显示“未发现结构化问题”。点击开始检查后出现“当前打印板为空”和原生配置校验不可用；左侧却显示“模型导入 完成”“颜色处理 完成”，右侧“模型与材料 完成”。现场没有模型。

错误正文直接拼接 `No printable object on plate.` 等英文诊断。重新打开侧栏后，完整的原生校验提示为 `Native configuration validation is unavailable until the current plate has a valid slice.`，侧栏扩展到约半个窗口宽，开始检查按钮禁用，仍没有“导入模型／返回生成页”之类的处理入口。

源码：`SmartSlicingPanel.cpp:304` 把空问题列表直接解释为无问题；`SmartSlicingViewModel.cpp:91` 附近在风险状态把第一步和旧流程部分阶段统一设成完成；`SmartSlicingPanel.cpp:312` 拼接原始 evidence。

建议：区分“尚未检查”和“检查通过”；“完成”必须对应已发生且通过的用户步骤。空板时明确显示“先添加模型”，提供本地导入及返回生成页入口；技术诊断折叠显示。

### 3. P1：智能切片难以发现，并且存在两套相似入口

**证据：实际操作 + 当前源码。** 3D 生成在顶栏，智能切片要到“主菜单 → 视图 → Show Smart Slicing”才能找到。相同菜单底部还保留“Show AI Assistant”。打开后是另一套英文 Ask、Accepted changes、Rejected changes 面板，用户不清楚两者适用场景。

准备页左侧“AI 自动流程”六步，智能切片右侧四步，含义与状态也不一致；同时占用两侧空间。

源码：`MainFrame.cpp:3173`、`1388`，`SmartSlicingFeatureHost.cpp:192`。

建议：在准备页切片按钮附近提供中文“智能切片”；生成导入完成后的下一步可以直接打开它。统一流程状态展示。旧助手若保留，应明确用途并移入高级工具，避免与主旅程竞争。

### 4. P1：确认应用之前，看不到具体要改什么（源码确认）

候选卡片展示时间、材料、支撑和相对基线差值，但没有参数的旧值／新值、对象姿态变化或具体方案说明。`SmartSlicingCandidateView.explanation` 虽被填充，Panel 没有展示；参数补丁和摆放变化也未进入显示模型。

源码：`SmartSlicingPanel.cpp:332` 起的卡片渲染、`SmartSlicingViewModel.hpp:24`、`SmartSlicingViewModel.cpp:32`。按钮叫“确认并应用”，实际应用后还会启动正式切片，见 `SmartSlicingCoordinator.cpp:337`。

建议：确认区展示“将改动：支撑、裙边、姿态等”，允许展开旧值／新值，保留现有耗时耗材比较；按钮改成“应用并切片”并说明下一页。不能仅凭节省了多少时间让用户批准配置变更。

### 5. P1：成功后缺少可发现的“撤销本次应用”（源码确认）

`SmartSlicingViewModel.cpp:15` 只在 `ApplyFailed` 时开放专用撤销；`SmartSlicingCoordinator.cpp:419` 也只接受该状态。成功后入口隐藏，用户看过预览再决定退回原方案的旅程中断。

限制：`SmartSlicingFeatureHost.cpp:239` 使用原生快照，普通 Orca Undo 可能仍能撤销，本次未实测；不能把此问题表述为“全部无法撤销”。

建议：成功预览保留明确的“撤销本次应用／恢复原方案”，在工程发生后续变化时校验并解释是否仍能安全撤销。

### 6. P2：展开检查区域会改变主窗口大小，产生裁切和滚动负担

**证据：实际操作；源码提供可能原因。** 在约 1544×981 的生成页展开“检查与编辑”后，主窗口缩到约 1224×728；结果区域出现横向滚动，AI 设计图被挤出可见范围。最大化后可继续浏览。

源码中的多处 `wxCollapsiblePane` 使用默认样式，见 `ModelGenerationPanel.cpp:999`、`1133`、`820`，没有显式禁止调整顶层窗口。确切根因需修改后复测，不能仅凭构造方式定论。

建议：折叠区仅调整内部布局，保持主窗口位置与大小。窄窗口时将两张参考图移到模型下方或提供明确切换，避免必须横向滚动才能比较。验证 1280×720、1366×768，以及不同 DPI。

### 7. P2：模型缩放与图片缩放的控制范围不清楚

**证据：实际操作 + 源码。** 首次看到恢复的模型时，头顶和底座被裁掉，右上却是“100%”且“适应”禁用。点击模型旁“摆正模型”后可以显示完整模型，证明模型没有缺失。

源码表明右上 −／适应／+ 控制的是图片，`ModelGenerationPanel.cpp:835`；“适应”在图片倍率已为 1 时禁用，见 `2920`。它们放在整个预览区顶栏，容易被理解为控制大模型。

建议：模型旁明确区分“显示完整模型”和“正面视角”；图片缩放放到图片卡片内部。恢复任务或布局变化后的初始构图应可理解，保留用户主动缩放时也要能清楚地一键复位。

### 8. P2：风险提示和返工动作距离太远

**证据：实际界面 + 当前源码。** 显眼区域提示“人脸和材料边界需复核，建议重新优化”，主要可见操作却是“导入到准备页”“重新开始”。改善结果的工具藏在“检查与编辑（可选）”及更深处；用户不知道重新开始会保留什么。

源码 `ModelGenerationPanel.cpp:2036` 表明完成模型重新开始会保留历史模型及可复用输入；`1169` 附近有“应用到下一次生成”，但它在折叠区域内。导入警告同样建议重新优化，却只给是否继续的选择。

建议：风险卡旁直接提供“修改描述重新生成”“局部改色”，明确保留当前版本。不同原因导向不同工具：脸型问题不要导向改色；串色问题优先导向颜色修正。

### 9. P2：历史模型缺少视觉识别，诊断信息占据主要位置

**证据：实际浏览 + 当前源码。** 历史记录主体是 OBJ、文字描述、文件大小、三角面数及完整 3D Task ID，没有缩略图。若连续迭代同一个人物或物件，容易出现同名或相似描述，找回正确版本需要反复加载。

源码：`ModelGenerationPanel.cpp:4738` 的 `refresh_library()`。当前只把文件格式作为左侧标记，把服务 Task ID 放在常显行。

建议：优先显示缩略图、短名称、版本时间和状态；面数、文件大小及服务 ID 放入详情。“复用造型”与“加载查看”解释清楚。历史页上方还沿用“确认主体、姿态与细节”的文案，宜随页面切换。

### 10. P2：多视图占用很小的图片卡，缺少聚焦检查体验

**证据：实际切换。** “模型多视图”将五个角度压进右侧约 215 像素宽卡片，单个角度很小。虽然可以通过图片缩放操作查看，但很难在同屏快速核对人脸和材料边界；上方还有“完成预览后会显示颜色映射和小色块处理数据”的占位说明，当前已经有完整结果。

建议：提供单角度大图切换／展开查看，保留角度名；有结果时移除与当前状态无关的占位文字。生成前的 AI 设计图与生成后的模型多视图要明确标识用途。

## 已观察到的合理设计

- 顶部“3D 生成”入口清晰，原图、设计图和模型能在同一工作区比较。
- 在生成、历史、准备页之间切换后，输入、配色与结果仍保留。
- 取消导入后的文字明确说明模型仍保留在本地，可重新导入；需要修复的是同步的进度状态。
- 本地检查与 AI 视觉复核在源码中分别提供说明，具备区分本地操作和服务操作的基础。
- 模型完整显示可通过“摆正模型”恢复，普通准备页与原有配置仍可访问。

## 建议修改顺序与复验

1. 先统一取消、空板、风险、成功状态与下一步按钮，消除误导性的“完成”和持续进度。
2. 整合智能切片入口与流程，并补足“具体改动 → 应用并切片 → 成功后撤销”。
3. 修复折叠导致窗口变化，分开模型与图片缩放，提供直接返工入口。
4. 最后完善历史缩略图、多视图放大和诊断信息层级。

后续完整复验需要一个获准运行、与当前源码对应、配置隔离的测试实例：以合成图片和简单模型走完三种输入、1／4／6 色、图片重做、取消与离线恢复、颜色匹配取消与重新导入；再执行候选对比、明确应用、正式切片成功／失败及撤销。普通手动切片、项目保存重开和 AI 不可用时的行为也需实测。本报告没有以源码检查或旧记录替代这些结果。
