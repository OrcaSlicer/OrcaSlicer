## 本轮具体改进

| 环节 | 本轮改动 | 实际结果与限制 |
|---|---|---|
| 原色导入 | 关闭试色时不再隐式固定为六色；以可编辑的 12 目标色、边界清理 0 开始 | 实际可切换 6／12／16 色，目标色与实体耗材数量分开 |
| 配色交接 | 明确选择沿用当前试色，或从模型原色重新配色 | 两条路径均保留局部改色；显式六色试色可固定交接 |
| GLB 柔化保存 | 对受支持的静态 GLB 保留原 UV、图像、材质、节点和索引，追加位置及必要法线 | 实际婚照 979,020 面保持，原 BIN 全部保留；原件不变、历史可恢复 |
| 发梢修正 | 局部改黑并保护相邻白衣／手臂，再柔化、保存 | 8,490 个显式黑色面保留，4,993 个面被设为保护；避免全局替换唇色 |
| 人像设计图 | 增加中性漫射光、连续自然肤色、唇眼边界及保守精修约束 | 提示词测试通过；新设计图被拦截，尚无实际效果证据 |

12／16 目标色能保留更多原色信息，但自动映射到四耗材时仍出现发梢泛红；局部修正后重新分为 13／17 色时，还观察到额头／上段头发误映成唇红。最终打印候选采用手动核对的六色试色：首色改为黑色，再映射到四种已有材料。这一结果支持“提供可控的重新配色”，不支持“更多颜色必然提高打印色准”。当前自动匹配仍缺少头发、皮肤和嘴唇的语义区分。

局部改色后再次柔化的检查确认：2,837 个受保护顶点、503,692 个涉及未选中面的顶点保持不动，8,490 个面颜色覆盖全部保留。原婚照、设计图、原模型及三个本地修整版本均留在软件实际历史中，重启、切页和重新打开已验证。

既有混元接入、唇色小区域保护、黑白混色显示、四实体耗材配方和精确接缝修复来自前序修改，本轮保留并按相关范围复验，不重复计作新增实现。

## 同一模型的层高对照

| 项目 | 0.20 mm | 0.12 mm |
|---|---:|---:|
| 层数 | 369 | 615 |
| G-code 预计时间 | 5:03:26 | 8:31:18 |
| 总耗材 | 88.63 g | 104.34 g |
| 工具更换 | 590 | 981 |

两份 3MF 的全部 `.model` 条目和模型设置逐字节一致，包含几何、面涂色和实例变换；四种材料相同。唯一影响打印的设置差异是层高，首层仍为 0.20 mm。0.12 工程基于相同的 Standard 参数，只改层高，没有换用整套 Fine 预设。

0.12 的层高降低 40%，预计时间增加 68.5%（约 3 小时 28 分），用料增加 17.7%（15.71 g）。这些是软件切片结果，不是实测打印耗时，也不能换算为“人像效果提升 40%”。与前序 016-r5 的 5 小时 5 分、88.78 g 差异很小，且塔位等条件有所变化，不作为算法省料收益。

补查已取得同视角、同缩放、无遮挡的双人正面切片图。采用验证任务的最终 70／74 号图：Ctrl+6 正面、相同滚轮缩放。操作仅在线类型图例中隐藏支撑、支撑界面和擦拭塔，再切回耗材丝着色；实际打印支撑和六份 GLB／3MF／G-code 交付文件哈希保持不变。预览中 0.12 显示较密的横向层线，0.20 的额头和脸颊有较明显的宽面光影与轮廓分段；两档嘴唇、浅色牙齿、肤色脸颊和黑发均可辨。模型及面涂色本身没有改变。若优先验证人像表面细节，可选 0.12 作为试打候选，同时接受表中增加的时间和用料；这些屏幕观察尚不能证明实物质量优胜。

- 实际主窗口通过：可编辑分色、沿用试色／重新配色、导入取消、撤销重做、手工网格修复、两档切片导出、两份工程重开，以及 AI 历史与准备页状态保留。修复后保留 979,020 面、489,502 顶点，可切片；未将其宣称为完全水密证明。
- 首次切片的擦拭塔越床已在测试工程中修正，失败工程单独保留；之后两档模型和塔坐标相同。
- 原生默认端口 18764 与用户已有 Orca 实例冲突；测试使用独立 18765、会话鉴权、父进程绑定及原安装版 bootstrap 连通。默认端口多实例冲突仍存在。

- GLB 保贴图柔化目前只支持限定的静态结构；局部改色版本使用顶点色。当前软件预览／打印仍有顶点或面颜色采样限制，未实现完整原分辨率 UV 打印。
- 保贴图柔化文件从约 28.5 MB 增至 40.7 MB，这是追加几何数据以保留原数据的代价。视觉柔化差异较轻微，没有实证证明人脸相似度提高。
- 未做实物肤色／唇色、支撑拆除或打印质量验证；没有打包、推送、发布、操作打印机或联系测试者。

## 新生成受阻的准确范围

本轮新图提交动作 `mcp__node_repl__js / sky.click(x188,y900)` 被自动审批审查拒绝，原始理由是私人婚照及详细人像描述可能发往未明确授权的外部图像服务。只读查明实际配置为 HTTPS 域名 `v.3dprint.beer`、模型 `gpt-image-2`。当前没有适用于该动作的正式批准回执或可调用复核入口；没有换工具、任务、服务或载荷重试。

同时检查了不依赖新生图的主窗口路线：现有婚照历史仅有已完成的 ready 任务及本地派生，没有独立待确认设计。加载已完成模型会清空活动任务，而生成要求非空、待确认任务，现成界面不能直接以该已完成记录发起两家新模型比较。此处是当前流程的依赖限制，不代表全部 3D 服务被永久禁止。未修改历史状态或通过 API 提交。

本轮实际提交：图像 **0**，Tripo **0**，混元 **0**，新 3D **0／20**，剩余额度 **20 次**。旧 Tripo 任务 `1e450375-7576-40df-b480-3260db1a2b35` 仅作已有模型来源。
