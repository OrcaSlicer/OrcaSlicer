# 最接近真实且可美颜的人像 3D 打印技术路线

> 文档状态：Proposal / 待工程审视  
> 版本：v1.0  
> 日期：2026-09-06  
> 适用项目：基于 OrcaSlicer，已接入 GPT 与 Tripo 的 3D 模型生成页面  
> 已知硬件：6 色固定耗材 FDM、6 通道 CMYK/过程色能力，喷头支持向下兼容  
> 本轮目标：先形成可验证的目标架构与审视标准，不直接要求修改现有代码

---

## 0. 执行摘要

本项目的人像目标不应定义为“把一张照片转成一个有贴图的模型”，而应定义为：

> **在保持人物身份特征的前提下，生成经过受控美颜、符合制造约束、并能在指定 6 色 FDM 或 6 通道 CMYK 硬件上稳定复现的人像打印资产。**

建议将整条链路拆成六个彼此可验收的模块：

```text
采集与质量门控
→ 人像语义理解
→ 身份优先的头脸几何重建
→ 受控三维美颜与艺术统一
→ 面向打印的几何/颜色编译
→ OrcaSlicer 切片与实物闭环
```

核心判断如下：

1. **真人相似度首先来自几何关系，而不是毛孔和高分辨率贴图。**眼距、鼻翼、嘴形、下颌、侧脸、发际线和个人不对称特征比皮肤微纹理更重要。
2. **Tripo 可以继续作为主链路的重要组成，但不应单独承担人物身份几何。**更适合补全头发、服装、胸像与整体有机造型；脸部需要独立的身份保持层。
3. **美颜应在真实重建之后，以三维语义参数进行。**不能只把输入照片先磨皮、瘦脸，再让生成模型猜三维形状。
4. **6 色固定耗材 FDM 与 6 通道 CMYK 是两个不同后端。**前者是离散材料选择与区域分色；后者是设备标定、色域映射和通道配方求解。
5. **视觉预览模型和制造模型必须分层。**建议使用 GLB 作为视觉/编辑母版，使用 3MF 作为制造母版，并区分通用制造 3MF、Orca 项目 3MF 与切片后的 G-code 3MF。
6. **质量评价必须包含实物打印。**屏幕渲染、人脸识别分数或切片成功都不能代替真人盲测、肤色误差、打印缺陷和重复性评价。

默认产品模式建议设为“**轻度精修半写实胸像**”：高身份相似度、低恐怖谷风险、颜色克制、发型和五官经过打印补偿。完整 360° 照片级真人应作为后续高阶模式，而非第一阶段默认目标。

## 1. 范围、已知条件与待确认项

### 1.1 已知条件

- 当前产品基于 OrcaSlicer 进行切片相关开发。
- 已有模型生成页面，接入 GPT 与 Tripo，并完成了一部分功能。
- 硬件支持 6 色固定耗材 FDM。
- 硬件支持 6 通道 CMYK/过程色能力。
- 喷头具备向下兼容能力，但有效通道组合、喷头拓扑、材料混色方式仍需从工程与硬件协议确认。

### 1.2 本文不做的假设

本文不假设：

- 六个 CMYK 通道一定是 `C/M/Y/K/W/透明`、`C/M/Y/K/浅青/浅品红` 或任何固定组合；
- 过程色通过同喷嘴比例混合、逐层交替、空间网点、多喷头叠加或其他方式实现；
- OrcaSlicer 当前版本已经原生支持全部六通道颜色求解；
- Tripo 输出天然水密、尺寸正确、颜色可直接进入切片；
- 单张照片能够可靠恢复人物侧脸、耳朵、后脑和发型背面。

上述内容必须由 Codex 通过代码、配置、协议文档或实物测试确认。

### 1.3 产品非目标

第一阶段不以以下效果作为强制目标：

- 单张照片生成完全准确的 360° 数字替身；
- 打印出皮肤毛孔、单根睫毛、单根发丝等渲染级细节；
- 未经设备标定，直接用通用 RGB→CMYK 公式获得准确肤色；
- 只靠一个“美颜强度”参数完成全部身份、神态、肤色和打印补偿。

## 2. 成功标准：把“像、好看、能打、稳定”分开衡量

人像质量不能用一个“模型质量分”概括。建议至少拆成五个目标：

| 目标 | 定义 | 主要决定因素 | 验收方式 |
|---|---|---|---|
| 身份相似度 | 一眼能够认出是本人 | 头脸比例、五官关系、侧脸、发际线、个体非对称 | 本人/亲友盲测、关键尺寸、辅助人脸特征相似度 |
| 美观度 | 比原始采集更上相但没有换脸 | 肤色、神态、发型、局部几何微调、风格统一 | A/B 偏好、本人确认、换脸感投诉率 |
| 打印可制造性 | 能切片、能稳定打印、关键细节不丢失 | 水密、壁厚、最小特征、朝向、支撑、颜色小岛 | 网格 QA、切片 QA、实物缺陷统计 |
| 颜色真实度 | 肤色和关键局部不灰、不脏、不蜡 | 去光照、设备色域、材料标定、通道求解 | 色卡与人像区域 ΔE00、重复打印差异 |
| 可重复性 | 同一输入和同一配置可复现 | 版本锁定、Profile、随机种子、缓存、配置记录 | 重跑一致性、跨设备/批次回归 |

建议产品级综合目标采用加权而不是单一最大化：

```text
PortraitScore =
  w_identity × IdentityScore
+ w_beauty   × BeautyPreference
+ w_print    × PrintabilityScore
+ w_color    × ColorFidelity
+ w_repeat   × Reproducibility
- w_uncanny  × UncannyPenalty
```

默认权重应满足：

```text
身份相似度 > 打印可制造性 > 美观度 > 颜色真实度 > 微观细节
```

在 CMYK 精品模式中，可提高颜色真实度权重；在 6 色 FDM 艺术胸像模式中，可提高几何和轮廓权重。

## 3. 产品模式设计

不要只提供“写实/卡通”两个开关。建议建立受约束的四档模式：

### 3.1 真实纪实

- 身份优先级最高；
- 几何修饰很低；
- 保留年龄特征和自然不对称；
- 只处理采集噪声、明显光照污染和不可打印细节；
- 适合长辈、家庭纪念、商务礼品。

### 3.2 轻度精修（建议默认）

- 保持眼距、鼻形、唇形、下颌和侧脸；
- 弱化黑眼圈、痘印、局部色差和过深法令纹；
- 轻微调整神态、发型体积和轮廓整洁度；
- 目标是“影楼修片后仍然是本人”。

### 3.3 影楼肖像

- 肤色更统一，气色更健康；
- 眼神、嘴角、眉形和发型更精修；
- 几何修改仍受身份约束；
- 适合礼品和社交分享。

### 3.4 风格化精修

- 可以进入轻偶像、雕塑、版画、低多边形等方向；
- 应明确提示身份细节会让位于风格；
- 不与“最真实”模式混为一谈。

产品 UI 应同时展示：

- 身份保持强度；
- 美颜强度；
- 神态；
- 年龄感保留；
- 发型整理；
- 输出硬件后端；
- 预计颜色/材料策略；
- 预估打印时间与换料成本。

### 4.1 模块边界原则

- GPT 负责理解意图、生成结构化计划、解释结果和调度工具，不直接等于几何算法。
- Tripo 是生成器，不是制造编译器。
- 人脸身份几何必须能独立于头发、服装和风格修改被锁定与回归测试。
- OrcaSlicer 负责切片与打印工艺，不应被默认承担人脸识别、三维美颜或过程色逆向求解。
- 颜色编译必须使用真实硬件和材料标定数据，不能只根据屏幕 RGB 工作。

## 5. 输入采集：质量上限首先由采集决定

### 5.1 推荐输入层级

| 级别 | 输入 | 建议用途 | 风险 |
|---|---|---|---|
| L0 | 单张正面照片 | 正面浮雕、概念预览 | 侧脸与后脑完全依赖猜测 |
| L1 | 正面 + 左右 45° | 低成本胸像 | 耳朵、侧脸和发型背面仍不稳定 |
| L2 | 8～12 张多视角 | 默认高质量胸像 | 需要采集引导与一致光照 |
| L3 | 环绕视频自动抽帧 | 消费级推荐入口 | 需要去模糊、去重复、姿态筛选 |
| L4 | 多相机/深度/扫描 | 精品或专业服务 | 成本与产品复杂度高 |

### 5.2 采集规范

建议页面实时提示：

- 使用主摄中长焦或避免超广角；
- 相机与人脸距离尽量稳定；
- 使用柔和均匀光线，避免强顶光和强侧光；
- 关闭系统美颜作为几何重建输入；
- 头部保持稳定，拍摄设备绕人移动；
- 表情保持自然、轻微闭嘴微笑或中性；
- 避免头发大面积遮挡眉毛、眼睛、耳朵和下颌；
- 眼镜反光严重时补拍无眼镜版本，用于几何重建，再单独恢复眼镜；
- 可选放置已知尺度标记，便于恢复真实尺寸。

### 5.3 采集质量门控

不合格输入应在调用昂贵模型之前被拦截：

- 人脸区域有效像素不足；
- 运动模糊；
- 曝光过度或严重欠曝；
- 视角覆盖不足；
- 相邻帧重复；
- 表情跨帧变化过大；
- 关键部位遮挡；
- 过强美颜导致五官边界消失；
- 多视角不是同一人物或发型/服装发生变化。

输出统一的 `CaptureQualityReport`，而不是只给“上传失败”。

## 6. 人像语义理解与身份锚点

在调用通用 3D 生成器之前，先建立独立的人像语义层：

- 稠密人脸关键点；
- 头部姿态；
- 表情/眼睛开合/嘴唇状态；
- 皮肤、头发、眉毛、眼白、虹膜、嘴唇、牙齿、耳朵、眼镜、服装分割；
- 阴影、高光、反射和妆容估计；
- 主要身份尺寸与比例；
- 遮挡和置信度。

建议构建 `IdentityAnchorSet`：

```json
{
  "version": "1.0",
  "coordinate_system": "head_local_mm",
  "anchors": {
    "interocular_distance": 63.2,
    "nose_width": 35.1,
    "mouth_width": 49.8,
    "face_width": 142.0,
    "face_height": 188.4,
    "chin_projection": 7.1,
    "left_profile_curve": "...",
    "right_profile_curve": "...",
    "hairline_curve": "..."
  },
  "asymmetry_features": [
    {"region": "mouth_corner_left", "preserve": true, "confidence": 0.88}
  ],
  "source_confidence": 0.91
}
```

这个数据不是为了替代网格，而是用于：

- 约束人脸重建；
- 防止 Tripo 或风格化模型改掉身份；
- 限制美颜幅度；
- 生成前后自动回归；
- 比较屏幕模型和打印模型是否发生关键特征漂移。

## 7. 身份优先的头脸重建

### 7.1 推荐职责划分

```text
脸部身份几何：人脸专用重建 + 多视角拟合
表情细节：专用表情/细节模型，必要时归一到打印友好状态
头发/衣服/胸像/后脑：Tripo 或其他有机生成器
眼镜/首饰/底座/文字：程序化建模或结构化模型
```

可以评估 MICA、DECA、SMIRK、FLAME 系工具作为研发候选，但必须独立检查：

- 是否恢复真实尺度；
- 是否能接收多视角或视频约束；
- 是否输出完整头部还是仅面部区域；
- 是否保留个体身份与不对称；
- 是否能合法商用；
- 是否能稳定转为闭合打印网格。

这些模型的研究结果可以作为部件，不应直接被视为成品商业链路。

### 7.2 Tripo 在链路中的正确定位

Tripo 当前支持单图和多视角模型生成。项目应优先验证多视角入口，但必须保留以下边界：

- Tripo 输出的人脸相似度需要被身份锚点验收；
- 不能因为贴图看起来像，就认为几何已经像；
- 不能让“再生成”“美化”“重拓扑”无约束地改变眼距、鼻形和下颌；
- 应保留原始输出、处理后输出和版本/参数记录；
- 头发、眼镜、牙齿、睫毛等薄片或透明材质必须经过打印实体化决策。

### 7.3 身份锁定合并

合并人脸专用网格和 Tripo 头发/胸像时，建议划分区域：

- **核心身份区**：眼眶、鼻、嘴、颧骨、下颌、下巴；禁止生成器大幅修改。
- **柔性过渡区**：额头、太阳穴、脸颊外缘、耳前；允许平滑融合。
- **生成补全区**：头发、后脑、颈部、服装、胸像；由通用生成器承担更多自由度。

合并前后至少比较：

- 关键比例变化；
- 正面、左右 45°、左右侧面轮廓；
- 人脸区域 Hausdorff/点到面误差；
- 辅助身份特征相似度；
- 人工 A/B 识别。

## 8. 受控三维美颜

### 8.1 核心原则

> 先恢复本人，再修饰本人；美颜是身份约束下的多层编辑，不是重新生成另一张更漂亮的脸。

所有美颜参数都应记录、可回退、可对比，并设置最大变化边界。

### 8.2 五层美颜模型

#### A. 几何美颜

允许小幅修改：

- 下颌线更整洁；
- 面颊凹陷轻度填平；
- 法令纹几何弱化；
- 鼻梁曲线去噪；
- 眼睑开合略微提升；
- 嘴角轻微上扬；
- 左右非身份性噪声平衡。

禁止默认大幅修改：

- 眼距；
- 鼻翼宽度；
- 唇形；
- 下巴长度；
- 侧脸投影；
- 人种、年龄或显著个人特征。

初始实验可把默认几何变化控制在局部尺寸的约 1%～3%，眼睑开合等神态参数可单独更高，但这些只能作为实验起点，必须通过真人 A/B 测试重新标定。

#### B. 肤质与 Albedo 美颜

建议顺序：

```text
原始图片
→ 颜色校正
→ 阴影/高光/环境光分离
→ 去光照 Albedo
→ 肤色均匀和瑕疵弱化
→ 设备色域映射
```

重点处理：

- 黑眼圈；
- 痘印、红斑和色斑；
- 眼周和鼻翼不自然暗区；
- 面部整体气色；
- 嘴唇、眉毛和发际线边界；
- 手机自动 HDR、美颜和白平衡污染。

必须避免：

- 把照片阴影直接印到脸上，导致真实光照下出现双重阴影；
- 过度磨皮后脸部失去结构；
- 肤色死白、偏灰或偏蜡；
- 用屏幕观感代替实物色卡结果。

#### C. 神态美颜

参数化控制：

- 中性；
- 自然微笑；
- 更精神；
- 更亲和；
- 更正式。

应限制眼睛、眉毛和嘴角的组合，防止出现“嘴笑但眼不笑”等不一致表情。

#### D. 发型与轮廓美颜

- 增加整体发量感；
- 整理碎发和穿插；
- 保护发际线身份；
- 单根发丝合并为发束和块面；
- 避免头发薄片、透明贴图或悬空细丝直接进入打印。

#### E. 姿态与构图美颜

- 轻微抬头、转头和肩部姿态；
- 优化胸像裁切与底座；
- 保持头部重心、支撑和打印稳定性；
- 不通过过度视角欺骗来掩盖几何错误。

- 日志、缓存、Tripo 上传地址和临时文件中不能泄露原始人脸或访问凭证。

## 9. 面向打印的几何编译

### 9.1 视觉细节与可打印细节的分界

| 数据 | 屏幕作用 | 默认能否打印 | 处理策略 |
|---|---|---|---|
| 三角网格 | 实际表面 | 是 | 修复、水密、厚度和尺寸校验 |
| Base Color/Albedo | 表面本色 | 取决于后端 | 转离散材料或过程色通道 |
| Normal/Bump | 光照伪凹凸 | 否 | 舍弃或选择性烘焙成真实几何 |
| Displacement | 可移动顶点 | 烘焙后可以 | 细分、限幅、几何化、再做最小特征检查 |
| Roughness/Metallic | 渲染材质 | 普通 FDM 不直接表达 | 映射到材料/后处理建议或舍弃 |
| Alpha 毛发片 | 透明渲染 | 否 | 重建为发束、实体薄片或删除 |
| Shader/后处理 | 视觉效果 | 否 | 烘焙或转为制造语义 |

### 9.2 共享制造准备层必须具备

1. 单位、坐标系、朝向与尺寸标准化；
2. 应用骨骼、Morph 和对象变换；
3. 移除内部面、重复面、漂浮碎片和不可打印透明片；
4. 检查并修复非流形、自交、孔洞和反向法线；
5. 体素/SDF 重网格或布尔合并；
6. 最小壁厚与最小独立部件检查；
7. 细小特征的保留、增强或删除；
8. 眼睛、牙齿、眼镜、头发和服装的实体化决策；
9. 生成支撑友好的姿态与底座连接；
10. 输出 `ManufacturingQAReport`。

### 9.3 人脸打印补偿

打印前需要有意识地强化：

- 上下眼睑边界；
- 鼻翼和鼻孔；
- 人中、唇峰与嘴角；
- 眉毛和发际线；
- 下颌与下巴转折；
- 头发大束之间的沟槽。

应主动压制：

- 毛孔；
- 细碎皱纹；
- 单根发丝；
- 眼球高光点；
- 贴图中偶然的阴影和反光。

补偿幅度必须由喷嘴、层高、成品尺寸、材料和朝向决定。不要在算法中写死一组毫米值。

### 9.4 初始实验参数（仅作标定起点）

对于常见 0.4 mm 喷嘴的小型胸像，可先建立如下实验档，而非产品硬编码：

| 项目 | 实验起点 |
|---|---:|
| 结构壁厚 | 1.2～1.6 mm |
| 独立发束/衣领 | ≥1.2 mm |
| 关键五官线宽 | 0.6～0.9 mm |
| 浅浮雕高度差 | 0.3～0.8 mm |
| 颜色小岛宽度 | 优先 ≥1.2 mm，低于值需合并/删除/转过程色 |
| 层高 | 由精品档 Profile 确定，面部区域可用可变层高 |

Codex 审视时应优先寻找现有硬件和切片 Profile 中的真实限制。

## 10. 6 色固定耗材 FDM 后端

### 10.1 正确定义

这是一个**离散材料/颜色选择问题**，不是连续 CMYK 配色问题：

```text
目标 Albedo
→ 读取当前装载的 1～6 种真实耗材颜色
→ 面向人像语义的颜色量化
→ 生成连续可打印区域
→ 分配 filament/material/tool
→ 优化换料与清料
```

### 10.2 人像语义优先的颜色预算

颜色不应平均分给整张模型。建议按价值排序：

1. 主肤色；
2. 肤色明暗/暖冷辅助色；
3. 头发与眉眼深色；
4. 唇色和气色；
5. 眼白/高光或服装主色；
6. 服装、底座或其他辅助色。

实际分配取决于当前装载材料，不应假设固定六色。

### 10.3 优化目标

```text
Loss_fdm =
  λ1 × perceptual_color_error
+ λ2 × face_semantic_error
+ λ3 × tiny_color_island_penalty
+ λ4 × tool_change_count
+ λ5 × purge_volume
+ λ6 × boundary_artifact
+ λ7 × print_time
```

应对眼睛、嘴唇、眉毛、鼻翼、发际线提高语义权重，对衣服背面和底座降低权重。

### 10.4 向下兼容

不能简单使用 `colors[:n]`。建议建模：

```json
{
  "backend": "discrete_fdm",
  "max_channels": 6,
  "supported_active_counts": [1, 2, 3, 4, 5, 6],
  "active_channel_ids": [0, 1, 2, 4],
  "supported_subsets": "from_hardware_profile",
  "filament_profiles": ["..."],
  "calibration_profile_id": "..."
}
```

不同通道子集需要重新量化颜色、估算成本和验证映射。

## 11. 6 通道 CMYK/过程色后端

### 11.1 正确定义

这是一个**设备特定的颜色正向模型与逆向配方求解问题**：

```text
目标设备无关颜色
→ 色域映射
→ 六通道配方/结构求解
→ 混色、层序或网点表达
→ 残留/串色/表面方向补偿
→ 切片或固件可执行指令
```

通用二维印刷的 CMYK 公式只能作为界面概念，不能作为最终设备模型。

### 11.2 必须先明确的硬件事实

- 六个通道的物理材料与角色；
- 单喷嘴、多喷嘴或混色腔拓扑；
- 能否同比例混合，还是只能切换/交替；
- 通道最小剂量、响应曲线和延迟；
- 清料长度、交叉污染和滞后；
- 不同层高、速度、温度和材料批次对颜色的影响；
- 水平面、斜面和垂直面的显色差异；
- 是否有白底、透明层或遮盖层。

### 11.3 颜色标定体系

建议建立版本化的 `PrinterColorProfile`：

```json
{
  "printer_model": "...",
  "head_topology": "...",
  "channel_set": ["ch0", "ch1", "ch2", "ch3", "ch4", "ch5"],
  "material_lot_ids": ["..."],
  "nozzle": "0.4mm",
  "layer_height": 0.08,
  "temperature": 210,
  "surface_orientation_bins": [0, 30, 60, 90],
  "measurement_illuminant": "D50_or_defined",
  "forward_model_version": "v1",
  "inverse_solver_version": "v1",
  "created_at": "..."
}
```

标定样件至少包含：

- 单通道阶梯；
- 两通道与多通道混合矩阵；
- 肤色高密度采样区；
- 低明度中性色，验证灰脏问题；
- 不同表面朝向；
- 不同层高/温度/速度；
- 通道切换与残留测试；
- 重复打印测试。

### 11.4 人像专用色域策略

优先保护：

- 肤色明度；
- 肤色黄红方向；
- 鼻翼和眼下的中性暗部；
- 嘴唇的红度和明度；
- 眼白不过蓝、不过灰；
- 发际线和肤色边界。

当颜色超出设备色域时，应优先保持肤色自然和局部关系，而不是机械追求全局最小 RGB 误差。

### 11.5 输出边界

过程色编译器应输出清晰的中间表示，例如：

- 每个三角面/体素/切片区域的目标设备颜色；
- 每层或每段路径的六通道配方；
- 允许 OrcaSlicer 理解的材料/工具语义；
- 或交给自定义切片/后处理模块的专用指令。

不能在没有证据时假设标准 3MF 的颜色属性会自动变成硬件需要的六通道运动控制。

## 12. GPT、Tripo 与 OrcaSlicer 的职责

### 12.1 GPT

应输出结构化 `PortraitGenerationPlan`，包含：

- 产品模式；
- 身份保持优先级；
- 美颜策略；
- 采集质量判断；
- Tripo/人脸重建任务计划；
- 输出尺寸和打印后端；
- 风格与风险提示；
- 失败后的可解释修正建议。

GPT 不应：

- 直接决定硬件通道配方；
- 根据文本猜喷嘴和材料限制；
- 用自然语言替代制造 QA；
- 在没有用户同意时自动修改敏感身份特征。

### 12.2 Tripo

应负责：

- 单图/多视角的通用模型生成；
- 头发、服装、胸像和整体造型补全；
- 必要的风格化候选；
- 输出原始网格和纹理供后续处理。

必须记录：

- API/模型版本；
- 输入文件哈希；
- Prompt、负面 Prompt 和参数；
- 任务 ID；
- 生成时间；
- 原始下载文件；
- 重试与失败原因；
- 商业授权和数据处理条款版本。

### 12.3 OrcaSlicer

适合承担：

- 切片；
- 层高、墙、填充、支撑和速度；
- 材料/工具分配；
- 换料、清料与时间估计；
- 打印机/耗材/工艺 Profile；
- G-code 生成；
- 切片结果回读与可视化。

不应默认承担：

- 人脸身份重建；
- 三维美颜；
- 去光照 Albedo；
- 人像语义分色；
- 六通道过程色的设备逆向求解。

### 13.1 推荐输出分层

```text
source/

slicing/

  output.gcode.3mf 或 output.gcode
  slice-report.json

qa/
  digital-qa.json
  physical-qa.json
  comparison-images/
```

### 13.2 GLB 与 3MF

- GLB 用于保存视觉模型、层级、网格、UV、纹理和网页预览；
- 3MF 用于保存制造几何、对象、颜色/材料属性和单位；
- 必须验证当前 OrcaSlicer 分支对所用 3MF 扩展的读取与保存行为；
- OBJ 只作为兼容输出，不作为唯一母版。

### 13.3 区分三类 3MF

- `manufacturing-master.3mf`：生成系统输出的制造资产；
- `orca-project.3mf`：包含 OrcaSlicer 项目、打印机、耗材和工艺上下文；
- `output.gcode.3mf`：切片后的 G-code 打包文件（若当前流程采用）。

不要把三类文件都命名为 `output.3mf`。

## 14. 质量评价与实验设计

### 14.1 三层验收

#### 数字模型层

- 多视角轮廓一致；
- 身份锚点误差；
- 网格完整性；
- Albedo 去光照质量；
- 美颜前后身份漂移；
- 颜色后端计划合法性。

#### 切片层

- 是否正确加载尺寸和对象；
- 材料/工具映射是否保留；
- 面部细节在切片预览中是否仍存在；
- 支撑是否接触关键面部区域；
- 换料、清料、时间和耗材是否异常；
- 当前通道子集是否真正生效。

#### 实物层

- 本人和亲友第一眼识别率；
- “像本人”和“更好看”分别评分；
- 恐怖谷/蜡像感评分；
- 肤色、嘴唇、眼周、头发的颜色误差；
- 层纹、接缝、支撑伤、串色和细节丢失；
- 同一配置重复打印一致性。

### 14.2 最小评测集

建议第一阶段建立经授权的 20～30 人内部评测集，覆盖：

- 不同性别表达；
- 年龄段；
- 肤色与面部特征；
- 长短发、卷发、白发；
- 眼镜与无眼镜；
- 胡须；
- 圆脸、长脸、明显侧脸特征；
- 中性和轻微微笑。

不要只使用团队里最容易生成的年轻、正面、无遮挡样本。

### 14.3 首轮关键 A/B 实验

| 实验 | A | B | 要回答的问题 |
|---|---|---|---|
| 输入 | 单图 | 多视角/视频 | 身份与侧脸提升是否值得采集成本 |
| 脸部 | Tripo-only | 人脸专用 + Tripo 合并 | 身份锁定的真实收益 |
| 美颜 | 无美颜 | 轻度三维美颜 | 是否更好看且不降低识别率 |
| Albedo | 原始贴图 | 去光照 + 精修 | 是否减少灰脏和双重阴影 |
| FDM | 通用 K-means | 人像语义分色 | 五官和肤色是否更稳定 |
| CMYK | 通用公式 | 实物标定逆向求解 | 肤色和中性色是否显著改善 |
| 几何 | 无补偿 | 五官打印补偿 | 打印后是否更像、是否过度雕刻 |
| 朝向 | 自动默认 | 人脸质量优化朝向 | 层纹和支撑伤是否降低 |

### 14.4 建议的阶段门槛

第一阶段不要追求绝对分数，可定义相对门槛：

- 多视角方案在身份盲测上稳定优于单图基线；
- 轻度美颜在“更好看”评分上提升，同时身份评分不显著下降；
- 去光照 Albedo 的实物人脸灰脏投诉率明显下降；
- 语义分色在相同颜色数下优于通用量化；
- CMYK 标定方案在肤色样片 ΔE00 和主观自然度上同时优于通用公式；
- 同一输入、同一 Profile 的重复打印结果可复现。

## 15. 建议的渐进式实施路线

### Phase 0：只读工程审视

目标：确认真实调用链、数据格式、硬编码和硬件边界。  
交付：当前状态报告、目标架构、验证矩阵、最小改动建议。  
停止条件：不得修改业务代码。

### Phase 1：建立可测量的当前基线

目标：不改生成效果，先让每一次生成和切片可追踪。  
建议交付：

- `PortraitGenerationPlan` 最小结构；
- 输入/输出哈希、模型版本、参数和 Profile 记录；
- 原始 Tripo 输出与送入 Orca 的文件关联；
- 数字 QA 和切片 QA；
- 5～10 个固定回归样例。

### Phase 2：输入质量门控与多视角

目标：减少不可恢复的低质量输入。  
交付：采集引导、自动抽帧、视角覆盖报告、Tripo 多视角实验。

### Phase 3：身份保持层

目标：脸部身份不再完全由通用生成器决定。  
交付：人脸专用候选评估、身份锚点、身份锁定合并、A/B 报告。

### Phase 4：受控三维美颜

目标：建立“更好看但仍是本人”的可回退编辑。  
交付：几何、Albedo、神态和发型四组参数；默认轻度精修；身份漂移门控。

### Phase 5：6 色 FDM 人像编译

目标：在有限颜色和换料成本下优化脸部观感。  
交付：实测耗材颜色库、语义量化、小岛合并、通道子集、成本与质量报告。

### Phase 6：6 通道 CMYK 标定与求解

目标：形成硬件专用颜色模型，而不是通用公式。  
交付：色卡、测量工具链、正向模型、逆向求解、方向/层高/残留补偿、肤色评价。

### Phase 7：产品化与反馈闭环

目标：让普通用户能稳定获得结果。  
交付：模式选择、采集指导、预览与打印差异提示、失败解释、用户确认和订单回灌。

## 16. 当前最可能的 P0 / P1 / P2 风险

### P0：不解决会让方向失真

- 6 色 FDM 和 6 通道 CMYK 共用一个抽象或一个分色函数；
- Tripo 输出未经制造 QA 就直接进入 OrcaSlicer；
- 网页预览使用带贴图模型，而打印实际只保留了白模或错误材料映射；
- 美颜只对输入图做 2D 滤镜，身份几何不可控；
- 没有记录模型版本、参数和输出文件关系，无法复现；
- 人脸图像、API 凭证或生成资产存在公开访问或日志泄露风险。

### P1：决定产品上限

- 没有人脸专用身份层和身份锚点；
- 没有去光照 Albedo；
- 没有人像语义分色；
- 没有设备专用 CMYK 标定；
- 没有实物 A/B 评价与回归样例；
- 向下兼容只是截断通道数组。

### P2：后续竞争力

- 自动选择最优产品模式与后端；
- 打印结果拍照/扫描后自动回灌；
- 个性化美颜偏好学习；
- 自动朝向、底座和支撑质量联合优化；
- 人像质量与成本的多目标搜索。

## 18. 推荐的第一款产品定义

### 默认产品：轻度精修半写实胸像

```text
输入：8～12 张多视角照片或环绕视频
身份：高优先级锁定
美颜：轻度精修，默认 20%～30% 感知强度
几何：五官和发际线打印补偿，毛孔与碎发抑制
输出：6 色 FDM 标准版 / 6 通道 CMYK 精品版
尺寸：由硬件和喷嘴 Profile 决定
文件：GLB 预览 + 3MF 制造母版 + Orca 项目
```

### 快速商业验证：精修人脸浮雕

- 单张正面照也能工作；
- 不需要猜完整后脑；
- 最适合验证去光照、美颜、肤色和正脸相似度；
- 适合作为相框、纪念牌、情侣/儿童/婚礼产品。

### 高阶产品：360° 高写实人像

只有在多视角采集、身份锁定、头发补全、设备颜色标定和实物 QA 全部稳定后推进。

## 20. 最终方向判断

项目不需要推翻现有 `GPT + Tripo + OrcaSlicer`，但需要把中心从“模型生成页面”升级为“人像制造系统”：

```text
GPT：意图和计划
Tripo：有机生成与补全
人脸专用层：身份几何
美颜层：受控语义编辑
制造编译层：可打印几何与颜色
双后端：6 色 FDM / 6 通道 CMYK
OrcaSlicer：切片和工艺执行
实物 QA：最终真值
```

真正的技术壁垒将来自：

> **身份保持、三维美颜、打印补偿、人像语义分色、六通道过程色标定，以及从预览到实物的一致性闭环。**
