# 本地语义配色

本功能针对有限耗材配色中的区域混淆：衣服被配成肤色、皮肤阴影误红、嘴唇被大面积肤色合并。识别器只判断图像中的区域；耗材选择由应用根据原色和当前候选颜色完成。首版不改变叠色物理模型或工程耗材配置。

## 代码边界

| 层 | 位置 | 职责 |
| --- | --- | --- |
| 领域接口与算法 | `src/slic3r/AI/ModelGeneration/SemanticColoring/SemanticColoring.*` | RGB8 输入、统一标签和置信度、可见面投影、多视图融合、区域配色、缓存格式、覆盖合成 |
| 模型适配器 | 同目录 `MediaPipeRegionRecognizers.*` | MediaPipe Tasks C ABI、原始类别和关键点转换、CPU 运行、校验版本、独立工厂 |
| 材质连续性 | 同目录 `SemanticMaterialRegions.*` | 只读原表面邻接、发束小亮岛和白衣阴影归并、受保护边界；只生成自动材料建议 |
| 后台协调 | `src/slic3r/GUI/AI/ModelGeneration/ModelSemanticColoring.*` | 不可变网格快照、任务取消、缓存、后台预览几何构建 |
| 主窗口衔接 | 同目录 `ModelPreviewSemantics.cpp`、`ModelPreview3D.hpp` | 轮询当前任务、显示状态、采纳结果、预览与导入共享覆盖合成 |
| 控件和保存 | `ModelPreviewColorControls.hpp`、`GUI/AI/Model/ColorTrialState.hpp` | 人像区域优化开关、完整候选色卡、试色状态兼容恢复 |

`IBodyRegionRecognizer` 与 `IFaceRegionRecognizer` 可以分别替换。适配器的 `identity()` 必须包含模型内容和输出解释版本；同一身份表示相同输入/输出语义。标签和置信度与输入 RGB 图像逐像素对应。业务层不读取模型类别编号或 478 点索引。

在工厂中注册新实现后，通过独立运行目录中的 `providers.json` 选择 `body_provider` 和 `face_provider`。默认均为 `mediapipe.cpu.v1`。配置在下一次试色请求时读取；关闭再开启即可触发。请求冻结配置内容，配置变化会创建新的识别器并取消旧请求。不要直接用其他权重覆盖固定文件名：哈希校验会拒绝不匹配的资源。模型版本变化应使用新的适配器身份。

## 数据和交互

从已加载网格复制几何及原色，保留原始面编号。后台 CPU 光栅化生成多个原色视图，颜色、深度、面编号共用同一次可见性判定。人体区域和面部细节分别识别，再融合到原网格；动物和缺乏可靠人像证据的部分沿用原算法。

识别缓存绑定几何、原色、两个模型身份及处理版本。耗材变化只重新匹配颜色；人工修改不进入识别缓存。工作线程不直接调用界面，每次请求有递增版本和取消标记，旧任务结果不能覆盖新模型。原生单次推理为同步调用，取消在原生调用前后及业务处理阶段生效。

耗材匹配使用完整候选颜色，允许多个区域复用同一耗材。已知人像卡保留皮肤、深色、浅色、唇色、冷色、中间色角色；其他色卡按原色距离和中性色保护选择。区域名称不表示强制目标色：红衣、红发、灰唇仍需要原色支持。

棕黑头发的自然明暗变化共享连通区域的稳健主材质；候选匹配避免把棕色高光送入人像卡的肤色或唇色槽，普通色卡中仍可选实际棕色耗材。明显红发、金发、灰白发及有面积支持的染色区域保留独立颜色。发梢低置信区域只允许从可靠头发种子沿相近原色补全最多三条共享边，且限制在原模型对角线的 0.8% 距离内。原色突变、可靠衣料／皮肤、贴着可靠皮肤的未知眼部轮廓、非流形或重复面都会阻止补全。这是配色层的有界自动建议，不修改识别标签或其置信度；识别缓存仍可复用。

配色表达材质本身，场景光照负责显示几何的明暗。头发中没有面积支持的孤立白色高光归入已有材质中心，不单独占用白色耗材。原图烘焙的光照与真实纹理不总能仅靠 RGB 区分；此策略不是通用的反照率恢复，也不把整件衣服或眼部无条件压成单色。

COL-003追加EyeSclera／Iris统一标签，旧标签值不变，识别缓存升级到v3。适配器内部把眼裂与虹膜椭圆转换为区域掩膜；眼睑和虹膜窄边缘放弃覆盖，无效／闭合眼睛回退。领域层按可靠眼区使用一个稳健材质中心，眼白暖反光／灰阴影优先选已有浅中性材料；小虹膜高光不额外拆色。最多四张脸分别提供细节证据，模型身份包含拓扑和掩膜版本。

COL-004在自动匹配末尾执行独立材质归并，人工层仍在其后合成。仅配色邻接按完全相等坐标连接，重复／非流形／反向表面阻断。小亮岛必须有可靠暗发周边、面积和空间窄度支持才继承已有发色；白衣阴影必须连到可靠浅色衣料主体，有面积支持的突变灰条保留。所有皮肤、嘴唇、口腔、眼部、配饰禁止重染；其旁未识别区域沿表面距离保留模型对角线0.5%的窄带。原始网格、颜色和识别标签不变。当前验收状态及具体阈值实验见[迭代台账](../plans/model-coloring/iterations.md)，这两项并不消除整面材料边界的三角分辨率限制。

候选槽的匹配依据与用户编辑后的目标颜色分别保存。手动把绿色色块改成蓝色时，原先属于绿色的区域改为蓝色，不因重新竞争候选色而意外变灰。更换整套耗材或色卡则建立新的候选关系。

人工修改与自动建议分别保留，合成顺序为人工修改、已启用自动建议、已有全局匹配。自动结果在预览中用锁定面色显示，导入沿用同一合成函数。关闭人像优化、关闭试色或选择原色导入时，自动覆盖不进入导入请求。旧的试色存档缺少语义字段时恢复为关闭，避免重新解释用户已有配色。

保存的 3MF 保留最终耗材分区，不单独携带可编辑的人工与语义图层。人工面片修改、试色配置和语义来源分别保存在美颜版本的 sidecar 文件中，自动区域标签保存在可重建的识别缓存中；仅复制 3MF 不会迁移这些可编辑状态。

## 本地资源与检查

固定模型、DLL、来源和许可证见 [原生适配说明](../../src/slic3r/AI/ModelGeneration/SemanticColoring/README.md)。应用不启动 Python、Torch 或 CUDA 来执行区域识别。此首版原生实现支持 Windows x64；其他平台可编译接口和回退实现。

构建时设置 `ORCA_SEMANTIC_RUNTIME_DIR` 为校验后的资源目录，安装后资源位于 `<exe>/ai/portrait_semantics`。构建不隐式联网下载资源。缺失资源或普通推理错误保留已有配色。

相关检查：

```text
python scripts/verify_ai_integration.py --json
slic3rutils_tests "[SemanticColoring]"
slic3rutils_tests "[ColorTrialState]"
```

领域单元测试、原生 ABI 测试、真实模型对照和主窗口验收分别记录，任何一个都不能替代其他项目。实际打印色差和叠色校准不属于这些屏幕配色检查。

官方 MediaPipe 二进制存在统计上报逻辑；本机处理输入不等于零联网。测试进程中拒绝 HTTP 发送时两张人像仍完成推理，但这不代表完整主窗口的整机断网验收。详细证据及原生 fatal error 的回退边界见原生适配说明。
