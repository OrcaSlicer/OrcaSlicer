# Orca AI 第一性原理开发优化计划

**Goal：** 提高给定尺寸、材料和打印模式下，用户一次接受实体成品的比例，同时降低达到该结果的总时间、费用和返工次数。

**Architecture：** 保留 Orca 的工程、配置、切片和项目保存能力。模型生成保存几何与连续外观母版，通过可追溯版本和交接协议派生离散耗材映射、CMYK 工艺方案及质量证据；上层显式编排，模型导入仍停在准备页。先修已证实的局部缺陷，再用实验决定路由和架构投入。

**Tech Stack：** C++17 / wxWidgets / Python / unittest / Catch2；本地 Graphify 0.9.54 和 Archify 2.16.0 离线模板。沿用现有六角色和集成流程，按小批次执行并保留验证回执。

## 每次交付都要能回答的指标

| 维度 | 评价对象 | 最小记录 |
| --- | --- | --- |
| 还原与身份 | 灰模几何、连续外观，分别与输入证据比较 | 关键形体/五官/姿态是否保留；缺失、推测和改造项 |
| 外观与审美 | 连续外观与制造预测分开 | 材质归属、身份关键小色区、可达颜色与细节损失 |
| 可制造性 | 指定尺寸、喷嘴、层高、材料、支撑和打印模式 | 网格检查、试切片、实物结果分别记状态；未知不记为通过 |
| 总时间与总成本 | 从用户输入到接受成品 | 各阶段等待、主动操作、生成次数、材料/冲刷、打印时间、失败和返工 |

每个实验结果绑定输入哈希、母版/派生版本、供应商任务及可得的模型参数、工艺配置和评价版本。成功率分母包含失败、超时、取消和人工补救；不以面数、单个质量分或图谱规模替代成品质量。

## Graphify / Archify 的日常开发用法

- 改动前：Graphify 查询目标符号的调用者、被调用者和相关文件；补查 C++ 成员/虚调用、wx Bind/CallAfter、HTTP 路由等缺边，回到源码核验。
- 改动后：只刷新受影响源码及必要依赖，记录源码哈希和前后关系变化；检查是否引入跨领域耦合。图谱差异用于提醒，不自动批准或拒绝代码。
- Archify 保留上一轮三张现状图，另画清楚标注“规划”的目标图。每个合并批次只更新实际改变的数据流、边界或状态，再校验布局与离线资源。
- 证据、源文件、测试命令、结果、缺失项和固定提交 SHA 随批次保存。工具不接收密钥、用户照片或实际模型作为代码索引输入。
