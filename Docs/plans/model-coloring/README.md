## 优化方向和当前计划

耗材配色表达材质固有色。头发、皮肤、眼白、虹膜和衣服按其区域与材质处理；原贴图中的阴影、高光、反光不应机械地变成新的耗材色。真实染发、花纹和独立色块需要原色与面积／空间证据支持。

| 顺序 | 工作项 | 要解决的问题 | 当前状态／完成条件 |
| --- | --- | --- | --- |
| 1 | 区域识别 | 眼白／虹膜混入肤色，嘴唇被吞并，多人脸细节遗漏 | COL-003 开发中。分别输出眼白和虹膜；在指定眼部放大区域验证原有串色减少 |
| 2 | 材质归并 | 发束亮条与衣物阴影被配为额外材料，白衣主体侵入相邻深色衣物 | COL-004 候选未通过。先修正衣料材质边界；必须同时保护方飞深灰绿内衬、刘亦菲白衣缝和颈部 |
| 3 | 颜色边界表示 | 眼睑、虹膜、发际线沿整面形成三角锯齿 | COL-005 待实现。先验证新掩膜；若整面分色仍限制边界，接入仅边界面的受限子三角材料分区，预览／导入共用 |
| 4 | 有光照的表面显示 | 眼球表面显三角块，影响观察 | COL-006 已诊断、待实现。共用保折角的着色法线；不以显示平滑代替打印颜色边界修复 |
| 5 | 全流程和部署 | 新建议是否真正进入导入／保存，模型替换与资源故障是否可靠 | 每个可交付候选执行受影响流程；新模型能力必须重验缓存身份和回退 |
| 6 | 实际耗材标定 | 屏幕目标与实物打印色差 | 独立后续项；需要实物色样、测量与叠色条件，当前屏幕测试不提供这项结论 |

优先处理用户指定的刘亦菲头发／眼睛，再回归方飞、双人人像、动物及真实红衣／红发／灰白发样本。缺少可靠证据的区域保留回退和人工修正，不无限扩大涂色范围。

## 每轮记录方式

1. 在台账登记唯一编号、反馈日期、具体模型与区域、症状、已确认事实和待验证假设。改动较大时分成可单独评估的子项。
2. 固定对照版本、原始模型哈希、色卡、相机、原色和目标掩膜。临时诊断演示明确标“假设演示”，不写成已运行的算法效果。
3. 记录生产文件和主要规则变化。未提交版本保留基线提交＋完整补丁／新增文件快照或可验证源码副本＋哈希；记录构建产物的 EXE、DLL 和运行资源身份。只记录 EXE 不足以区分本项目算法版本。
4. 完成相关测试与同模型对照后，记录改善、回归、仍失败区域、耗时／内存以及实际执行的主窗口流程。尝试失败也追加记录，不删除。
5. 将结论标为“通过本轮范围”“部分改善”“未通过”“开发中”或“待验证”。需要继续的缺陷进入下一编号；保留旧结果。每次交付指向明确编号与运行目录。
6. 回退到已保留的完整源码／运行目录；不覆盖用户资产，不把旧导入的已固化 3MF 当作新算法自动重算结果。代码提交或远程推送仍按用户实际授权处理。

历史补录只采用现存证据。无法确认的日期、逐次补丁和效果写“未记录／未核验”，不补造实验经过。当前开发项只有完成构建和实际验证后才会晋级为可交付版本。
