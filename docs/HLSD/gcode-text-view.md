# Preview G-code text view — High Level Design

This document defines the interaction rules, state ownership and integration constraints for
browsing G-code text and navigating to toolpath positions in Preview.

## Purpose and scope

- Browse the G-code text window in Preview with the mouse wheel.
- Click a text line to navigate the preview to its corresponding toolpath position.
- Extend the existing ImGui panel, retaining syntax colors, memory-mapped file access and
  reading visible lines on demand.
- Keep the existing panel rather than introducing a native wx text control or a full editor.
- Retain the existing window visibility conditions, long-line truncation, file loading and
  error handling. There is no standalone text-only browsing mode.

## Existing mechanisms

### Reading and rendering text

`GCodeViewer::SequentialView::GCodeWindow` is defined in
`src/slic3r/GUI/GCodeViewer.hpp/.cpp`.

- `load_gcode()` receives a filename and `lines_ends`, and accesses the file through a memory map.
- `render()` reads its visible interval from `GCodeTextView`. Following centers that interval
  on the current toolpath's `gcode_id`; manual browsing keeps an independent first visible line.
- Line numbers, commands, parameters and comments have separate colors. Long lines are
  currently truncated to 55 characters.
- The line cache is invalidated by the displayed interval's first line and line count, so path
  changes during manual browsing do not trigger unnecessary reads or move the viewport.

### Existing window visibility conditions

- `GCodeViewer::render_overlay()` returns immediately when
  `m_viewer.get_extrusion_roles().empty()`. This collection is populated when `Extrude` vertices
  are loaded, so files containing only Travel or other non-extrusion paths also fail this check.
- `SequentialView::render_overlay()` renders the text window only when `has_render_path` is
  true. This argument currently comes from `!m_no_render_path`.
- `GCodeWindow::render()` requires the text visibility option to be enabled, a nonempty filename
  and line-offset array, and `curr_line_id != 0`. It also skips rendering when no lines fit.
- These conditions remain in effect. A file with no navigable toolpaths does not get a text-only
  window. This differs from loaded extrusion data whose paths are hidden by global filters.

### Line numbers and preview vertices

Conversion in `src/slic3r/GUI/LibVGCode/LibVGCodeWrapper.cpp` preserves each vertex's `gcode_id`
and the viewer's `layer_id`, and may add vertices at path starts.

`GCodeViewer::update_moves_slider()` already groups consecutive vertices sharing a `gcode_id`,
including the multiple segments generated by a single G2/G3 line. Source line numbers, viewer
vertex indices and slider positions are distinct identifiers and cannot be interchanged.

Some non-motion commands have event vertices; other lines have no vertices at all. The G/M
command name alone cannot determine whether a line has a corresponding preview position.

`GCodeNavigation.hpp` resolves source lines through an accessor into the existing vertex data.
For ordered source IDs it uses binary search and expands the selected consecutive group. A
missing line resolves to the greatest preceding source ID, or the first positive source ID
when no predecessor exists. The result retains both group endpoints; its last vertex matches
the move slider's command endpoint. Source ID zero is not a navigable file line. Nonmonotonic
data uses a linear fallback; repeated disjoint groups with the same source ID resolve to the
last occurrence. Ordering is checked once when a result is loaded, not on every click.

### Input and refresh

`GLCanvas3D::on_mouse()` and `on_mouse_wheel()` forward input through
`ImGuiWrapper::update_mouse_data()`. The text panel reuses this event path.

The panel uses a scrollbar over source-line offsets and disables ImGui's automatic wheel
scrolling. It reads only the visible rows, without creating a full-file pixel-height list.
`IMSlider` reports user interaction separately from its dirty state, so programmatic range
updates do not resume text following. Preview keyboard slider operations resume it explicitly.

`GLCanvas3D::_render_gcode_overlay()` processes the layer slider's dirty state before the move
slider's. Setting the layer range resets the visible toolpath range, so navigation across
layers must update the layer range and slider mapping before applying the target position.

The 3D scene is currently drawn before the text overlay. A click that changes the toolpath
position must request a full scene refresh, rather than refreshing only the overlay.

## Interaction and state

### State ownership

The text panel owns browsing and hit-testing state. `GCodeViewer` owns toolpath navigation.

The following states are distinct:

- The source line number corresponding to the current preview position.
- The first visible text line, or an equivalent scroll position.
- The text line selected by the user.
- Whether text follows the toolpath, and the reason for any viewport repositioning.
- A pending navigation request from a text click.
- The resolved navigation target's source line and vertex identity, independent of a slider
  index that can change when the layer range or global filters change.

The clicked line can differ from the current toolpath line, particularly for comments or
commands without vertices. A light background marks the clicked line; the existing outline
marks the toolpath line. These decorations are combined when both refer to the same line.

The text panel returns a target line number or stores a request for its owner to consume.
It does not depend directly on Plater or control the entire preview. The interface should make
the smallest changes needed to support these behaviors.

### Scrolling and rendering

- Support the mouse wheel and a draggable vertical scrollbar. The scrollbar reflects the
  browsing position and provides quick navigation through long files.
- Wheel and scrollbar input affect only the text viewport, reading newly visible lines on
  demand. They do not change toolpath progress, the layer range or the camera.
- Reuse the existing directional wheel steps and scroll by lines. Do not add smooth pixel
  scrolling or change scrolling behavior in other ImGui controls or preview sliders.
- Retain the current truncation and ellipsis for lines longer than 55 characters. Do not add
  full-line hover tooltips or a horizontal scrollbar.
- Create interactive regions only for visible rows. The line number and all colored text
  fragments share one hit region covering the entire row.
- Clamp the displayed interval to valid line numbers. Handle empty data, short files and
  window height changes safely without bypassing the existing visibility conditions.
- Avoid applying both ImGui's own scrolling and custom line-number scrolling to the same input.
- Preserve syntax colors and the existing file-size clamping when reading the mapped file.
- Do not parse the entire file or scan every toolpath vertex on each scroll event.

### Browsing and following the toolpath

- Manual wheel or scrollbar use leaves the text at an independent browsing position. Ordinary
  redraws and the pointer leaving the text window do not resume following.
- User interaction with the layer or move slider resumes following, including equivalent
  keyboard operations. The text is then displayed around the current toolpath line again.
- Clicking text requests navigation while preserving the viewport and entering independent
  browsing. Do not recenter the clicked line; this allows successive clicks without moving the
  text. Following resumes when the user operates a slider.
- Programmatic slider updates caused by a text click are not user slider interactions. They
  must not accidentally resume following or recenter the text.
- Do not add following/browsing status text or a button to resume following.
- While following, the scrollbar position remains consistent with the actual displayed interval.

### Click navigation semantics

- Clicking a line with corresponding vertices is equivalent to moving the existing move slider
  to that line's step. There is no separate choice between navigating to its start or endpoint.
- Reuse `update_moves_slider()` grouping and value selection for consecutive vertices sharing a
  `gcode_id`. Ordinary moves display through the command endpoint; G2/G3 arcs display through
  the end of the entire arc.
- Events, seams, retractions and other special vertices also use the existing slider mapping.
  Do not infer positions from command names or introduce separate selection rules for added
  vertices or seams.
- If a clicked line has no corresponding vertex, navigate to the nearest preceding navigable
  toolpath position in source order, while keeping the clicked text line selected.
- If neither the clicked line nor any preceding line has a navigable position, but a later path
  exists, navigate to the file's first navigable toolpath position. This covers comments and
  other lines without vertices at the start of the file.
- Lines without vertices at the end of the file use the same preceding-position rule and resolve
  to the last navigable toolpath position.
- If the entire file has no navigable toolpath, retain the existing visibility conditions;
  independent text browsing and selection are not enabled.
- Navigation changes only toolpath-related state. Camera orientation, position and zoom remain
  unchanged.
- Keep the outline on the current toolpath line and a light background on the clicked line,
  combining them when they coincide. Resolving to a nearby path does not move the text selection
  to that path's line.

### Layer and move ranges

- In normal multi-layer mode, each text navigation sets the target path's layer as the upper
  layer bound while retaining as much of the existing lower bound as possible: the new lower
  bound is the smaller of the old lower bound and the target layer.
- Update the upper bound even when the target is inside the existing range but below its top
  layer. For example, navigating to layer 20 from a range of layers 1–50 changes it to 1–20.
- If the target is below the old lower bound, lower that bound to the target layer as well.
  If single-layer mode is already active, preserve it and display only the target layer.
- Within the same layer, retain the existing move-slider behavior and lower move bound.
  If the target precedes that bound, the existing `SetHigherValue()` constraints move the lower
  bound back to the target too, allowing the interval to collapse to one position.
- When the layer range changes, finish the existing layer-change flow and rebuild the move
  slider mapping before applying text navigation. Do not reuse old slider indices in the new
  range. The lower move bound after a layer change follows the existing layer-change defaults.
- A global visibility change can also alter the enabled range and slider grouping. Preserve
  the navigation target and, for same-layer navigation, the lower move bound by source/vertex
  identity while rebuilding the mapping. Do not carry numeric slider indices between mappings.

### Enabling the target's global visibility categories

- If the resolved target is hidden, enable its corresponding global visibility category before
  applying the final navigation position. The legend reflects the enabled setting, just as it
  does after the user enables that category manually.
- Derive the required categories from the resolved command group's vertices. Extrusion vertices
  use their extrusion role; Travel, Wipe and event vertices use their existing
  `move_type_to_option()` category. If the group contains multiple renderable types, enable the
  categories required by that group. Leave unrelated settings unchanged.
- Reuse `is_option_visible()` / `toggle_option_visibility()` and
  `is_extrusion_role_visible()` / `toggle_extrusion_role_visibility()`. Query before toggling so
  repeated clicks leave an already enabled category enabled.
- For a comment or another clicked line without vertices, first resolve the preceding path or
  the file's first path using the navigation rules above. Enable the resolved path's categories
  while keeping the clicked text line selected.
- The change applies to the entire category within the normal layer and progress ranges, not
  just to the clicked line. For example, selecting a hidden Travel enables Travel globally;
  other Travel segments can then appear wherever the normal visible range includes them.
- Keep the enabled categories on after text scrolling, subsequent clicks, slider operations and
  closing the text window. Do not restore a filter snapshot. The user can turn a category off
  normally, and it remains off until the user or another text navigation enables it again.
- Clicking a different category does not turn previously enabled categories off. There is no
  visibility exception tied to the selected line and no extra visibility target to clear.
- Global filter lifetime and persistence follow existing application behavior. Text navigation
  does not introduce its own settings storage or override the normal load/reset behavior.
- For G-code with loaded extrusion data that meets the existing file and source-line visibility
  conditions, text remains browsable and clickable even if all path types are globally hidden.
  A click enables the resolved target's categories through the normal global filtering path.
  This does not extend support to files that otherwise fail the window visibility conditions.

### Window and file lifetime

- Closing and reopening the text window for the same G-code file preserves the browsing
  position, text selection and following state. It does not automatically recenter the text.
- Closing the text window does not change global visibility settings. Slider interaction while
  the window is hidden still resumes following, without restoring older filter settings.
- Reslicing, switching plates or loading another file clears the old browsing position, text
  selection, pending requests and navigation identities. Resume following the new preview's
  current path. Do not restore old browsing state when returning to a plate or file; global
  filters continue to follow the application's existing lifetime rules.
- Manual legend changes apply normally, including hiding the selected path if its category is
  turned off. This action does not reset the text viewport, text selection or following state.
  There is no special visibility rule that keeps the selected path visible against this change.
- Browsing state exists only for the currently loaded file during the application session.
  It is not persisted across application restarts.
- Window resizing and DPI changes trigger layout changes. While browsing, preserve the first
  visible line as far as possible and clamp the range. While following, continue displaying
  text around the current path line. Theme changes do not alter browsing or selection. These
  constraints preserve the interaction state across layout changes.

### Navigation flow

1. The text panel produces a target source line number.
2. `GCodeViewer` resolves it to a target vertex or a result indicating that no navigable path
   exists. Resolve against loaded source data, not only the currently enabled range; validate
   the result before changing visibility settings.
3. Capture the target's source/vertex identity and the existing lower move bound where it must
   be preserved. Apply the target layer range and enable any required global categories using
   the existing viewer operations.
4. Recalculate the final enabled range and rebuild the move slider mapping after those changes.
   Intermediate programmatic slider updates must not resume following or replace the captured
   target. Preserve the lower bound by identity when the layer range is unchanged; otherwise
   use the existing layer-change defaults.
5. Locate the target in the new mapping, apply the existing upper/lower bound constraints and
   synchronize the slider and visible progress. Never reuse a slider index from before a
   visibility or layer-range change.
6. Request a full scene refresh so the toolpath, nozzle marker and position readout update
   together.

Arc, added-vertex and event navigation use the existing slider mapping. Reverse lookup from a
source line should reuse existing data rather than introducing a second complete file index by
default. If binary search is used, verify that the searched data is ordered by line number,
including event and seam vertices.

Global visibility changes already pass through `ViewerImpl::update_view_full_range()` for range
calculation and `update_enabled_entities()` for submitted geometry and events. Reuse those
ordinary paths and their normal color/legend updates. No selected-line visibility predicate or
additional rendering pass is introduced.

### File loading and error handling

- Reuse existing `load_gcode()`, `reset()` and read-error handling. Do not introduce file
  monitoring, external-change notifications, automatic reload or another reload entry point.
- Preserve existing read bounds checks and UTF-8 truncation. This scope does not guarantee
  detection of all external changes, and clamping to the mapped size is not complete file
  change detection.
- When an existing load or reload flow produces a new result, apply the new-file reset rules
  and discard old line numbers, navigation requests and source/vertex identities.
- A click request is valid only for the loaded result that produced it. Discard it if that
  result changes or the required resources become unavailable before consumption. Never apply
  old vertices or line numbers to a new result.

## Integration boundaries and verification

Relevant modules and responsibilities:

- `src/slic3r/GUI/GCodeViewer.hpp/.cpp`: browsing state, visible-line caching, row interaction,
  line resolution and toolpath navigation.
- `src/slic3r/GUI/GLCanvas3D.cpp`: request consumption, ordering of layer and progress updates,
  scene refresh and input ownership.
- `src/slic3r/GUI/IMSlider.hpp/.cpp`: add only a minimal interface if needed to reuse mapping
  functionality.
- Reuse `ImGuiWrapper` wheel direction normalization. Do not redesign shared input handling for
  smooth scrolling.
- Reuse the existing libvgcode visibility query/toggle APIs. No selected-line visibility API or
  extra filtering layer is needed.

Independent scrolling requires fixing the existing line-range calculation risks around line 0
and unsigned underflow for short files. Wheel input inside the text area must not leak to the
camera or sliders; input outside it retains existing behavior.

Verification covers:

- Empty files, short files, the first and last lines, and a final line without a newline.
- Existing visibility conditions when extrusion vertices are absent, only Travel exists, or
  the current line number is unavailable. Independent browsing must not accidentally enable
  text-only mode.
- Existing truncation at 55 characters and UTF-8 handling. Wheel scrolling uses line steps;
  horizontal and zero-delta events do not cause additional vertical scrolling.
- Ordinary moves, multiple vertices sharing a line, arcs, added vertices, events and seams.
- Clicking a line with vertices resolves to the same position as its existing slider step,
  including arcs, events, retractions and seams.
- Lines without vertices resolve to the nearest preceding path; leading lines without a
  preceding path resolve to the first path; trailing lines resolve to the last path.
- The clicked line's light background and actual path line's outline remain distinct, combine
  when coincident, and do not move the text selection to a nearby path line.
- Navigation within and across layers, single-layer and multi-layer modes, and move lower bounds.
- The upper layer bound becomes the target layer while the lower bound is preserved where
  possible. Same-layer move bounds follow existing slider behavior; layer changes do not reuse
  old indices.
- Hidden Travel, extrusion roles and event categories become globally enabled as required by
  the resolved command group. Legend states update, already enabled categories stay enabled,
  and unrelated category settings do not change.
- Fallback navigation from a line without vertices enables the resolved path's categories.
  All segments of a target arc and other same-category paths obey the normal visible range.
- Successive clicks can enable additional categories without restoring previous settings.
  Scrolling, slider operations and window closing do not undo category enablement. Manual
  disabling hides the selected category normally until another explicit enable operation.
- Enabling a category that changes either end of the enabled range preserves the intended
  navigation target and applicable lower bound by identity, never by a stale slider index.
- Successive wheel scrolling, scrollbar dragging and row clicks; input isolation inside and
  outside the text panel; button press and release; and dragging beyond its bounds.
- Ordinary redraws and pointer departure do not resume following after manual browsing.
  User layer/move slider operations, including keyboard input, do resume following. Text clicks
  and their programmatic slider updates preserve the viewport.
- Reading on demand and navigation cost for large files.
- Closing and reopening the same file preserves text state. Slider interaction while the text
  window is hidden still resumes following and does not restore old global filter settings.
- Manual filter changes affect the selected path and every other path normally, while text
  browsing and selection remain intact. There is no special case retaining selected geometry.
- Reslicing, plate changes and loading another file reset old state, without reusing line
  numbers, vertex ranges or pending requests. Existing load/reload and mapping-error handling
  must not regress; new external-change detection is not required.
- Camera stability and consistent toolpath, marker and readout refresh.
- macOS trackpads, Windows mouse wheels and Linux GTK, including DPI and theme changes.

Line bounds, line-to-slider/vertex mapping and idempotent global category enablement are suitable
for targeted automated verification. Actual input capture, DPI behavior and visual consistency
across platforms require verification in the application.
