# Agent 开发交接模板

当任务需要后续 Agent 继续开发、复查或扩展时，复制以下模板填写。重点记录代码事实和未完成边界，不复述聊天过程。

```markdown
# 任务交接：<简短名称>

## 目标

<用户可见行为和明确的非目标>

## 当前状态

- 状态：未开始 / 实现中 / 已完成待验证 / 被阻塞
- 已完成：
  - <具体结果>
- 未完成：
  - <剩余工作>

## 关键调用链

`入口符号` -> `状态修改符号` -> `算法符号` -> `输出/刷新符号`

## 状态所有者

- 主要状态：`类型/成员`
- 生命周期：<谁创建、谁销毁>
- 线程：UI / BackgroundSlicingProcess / TBB / Network worker

## 已修改文件

- `path/file.cpp`：<修改目的>
- `path/file.hpp`：<修改目的>

## 配置影响

- option key：`<key>` / 无
- 作用域：printer / print / filament / object / region / plate
- 默认及关闭行为：<说明>
- 失效步骤：`pos...` / `ps...` / 无

## 持久化与兼容

- AppConfig：是/否
- Profile：是/否
- 3MF：是/否，旧文件缺失字段时 <行为>
- G-code：是/否
- 跨平台分支：<说明>

## 验证建议

- <最小场景>
- <开关关闭回归>
- <修改参数后二次切片>
- <保存并重开工程>

## 未解决风险

- <只写有证据的风险或 TODO>

## 仓库状态提醒

- 用户原有改动：<路径或无>
- 本任务新增未跟踪文件：<路径或无>
- 未执行的检查：<按 AGENTS.md 和用户要求如实记录>
```

## 好的交接信息

- “`wall_sequence` 在 `PrintObject::invalidate_state_by_config_options()` 映射到 `posPerimeters`。”
- “完成事件来自后台线程，通过 `wxQueueEvent` 投递到 `Plater`。”
- “新字段可选，旧 3MF 缺失时保持 false，完整工程加载才应用。”
- “功能关闭时直接进入原 `make_perimeters()` 分支。”

## 无效的交接信息

- “改了很多相关代码，请继续看看。”
- “应该没问题。”
- “可能在线程这里。”
- 只列文件，不说明调用链、状态所有者和剩余工作。

## 交接前最小检查

- 当前改动是否都属于用户任务。
- 是否误改了用户已有文件。
- 是否记录未执行的构建/测试，而不是声称已验证。
- 是否给出下一步可直接搜索的符号名。
- 是否说明配置、缓存、线程、持久化中不适用的项。
