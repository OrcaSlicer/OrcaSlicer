## `test_every_action`
`test_every_action.py` · Python, 511 checks

**Tests:** Runs all 129 Speed Dial actions of `tests/data/speed_dial_actions.json` through `action_run` on the Generic Klipper Printer 0.4, each from a state rebuilt by calls (empty project, two cubes, sliced plates, an assembled object, a recording, and so on), and answers the action's dialog or file picker as its row says. For each action it reads back the action's effect, then checks that the reply names the action, that the journal keeps an `action_run` step for it with the arguments its command journals, and that `action_search` maps it to the command in `tests/data/speed_dial_action_calls.json`.

**Starts from:** `start(client)`, which "starts from the Generic Klipper Printer" compares with `{printer: "MyKlipper 0.4 nozzle", process: "0.20mm Standard @MyKlipper", filaments: ["Generic PLA @System"]}`. That printer has no print host, which the `send_gcode` row needs: its system preset's `print_host` is empty, and `start()` discards unsaved changes. The test reads the mode it finds (`app_state.mode`), to put back at its end. The setup check `Start Recording's folder is the output folder` points the folder Start Recording and Take Screenshot save in at the output folder, through the Start Recording dialog. Before each row, `empty()` makes a new project with its changes discarded, shows Prepare's 3D view, deletes filament slots down to one and sets the expert mode, and the row's state builds on that. The `import_configs` row reads that the filament preset of its fixture, `tests/fixtures/mcp_import_pla.json`, is not loaded, so the start deletes a leftover `MCP Import PLA` with `preset_delete` when `preset_list` lists one (from a failed run, or an earlier sweep on the folder): the name is this test's alone, and the fixture's parent is `Generic PLA @System`, which every seeded folder has. The two plugin rows work on plugins only this run makes: `install_local_plugin` installs `every_action_install_<stamp>.py` and `refresh_plugins` side-loads the folder `orca_plugins/every_action_side_load_<stamp>`, copies of the fixtures `mcp_tools_fixture` and `mcp_web_fixture` whose manifests name them `MCP Every Action Install <stamp>` and `MCP Every Action Side-load <stamp>`, `<stamp>` being the run's start time. The fixtures' own names would not do: test_web_ui's setup side-loads `MCP Web Fixture`, enabled, into its job's data folder, which is this test's when the history runs test_web_ui alone, and a refresh then finds nothing new; a name only this run uses is absent before its row whatever ran before. The test is exclusive, so it runs on the serial tests' data folder and the runner never runs it twice on one folder.

**Leaves:** the two plugin copies in the plugins folder: the installed one on, as a local install leaves a plugin (`"enabled": true` in its `.install_state.json`), its actions labelled with its own name, and the side-loaded one off, as a plugin with no `.install_state.json` is (`PluginDescriptor::enabled`); Recent Projects' `saved.3mf`, `saved_as.3mf` and `load_me.3mf`, and the folders the app remembers for its last export and for settings files (`app.last_export_path`, `recent.settings_folder`), all in its output folder, which the runner deletes when the test passes; Start Recording's folder, the same output folder, so that a later capture with no path goes to the default capture folder, as on a new data folder (`folder_or_default()`, `RecordingDialog.cpp`); and an empty project with one filament slot. Its picks are `action_run` calls, which leave the Speed Dial's usage counts as they were. Developer mode and the camera's projection are put back by their rows' own post steps. It puts back the mode it found in a `finally`, since the mode decides which settings the sidebar and the settings tabs show to every test after it.

**Decides by:** Exits 1 when any printed `FAIL` check fails. A call error, or an uncaught exception from a row's lambda, also fails the test. Every action runs; none is skipped. What "passes" means depends on the row:
- Common to every row that runs (all but the 3 refused): `... its reply names the action it ran` (`ran` == `orca_command:<key>:orca`, skipped for `export_config`, whose dialog is cancelled). `... the journal keeps its action_run with the arguments its command journals` requires an `action_run` step of that id whose inner `args` equal one value exactly:
  - `{"percent": 50}` for `go_to_layer` and `{"tab": "preview"}` for `go_to_tab`, the values given for their input.
  - `{}`, no `args`, for every other action: its command journals nothing of its own, or, as for `obj_arrange` and `start_recording`, its action's fixed arguments are empty. The nine `calib_*` actions are among them: each opens its test's dialog (the person's form), and `calibration_generate_test` rewrites its journal entry (`ActionContext::set_journal_args`) only when it runs the test itself, with its parameters or `silent`.
  The test's docstring, which says every step carries the fixture's arguments, says this instead: an `action_run` step with the id alone replays the same, since the action supplies its fixed arguments.
  `... its action names the fixture's command` compares `action_search`'s `command` with the fixture's.
- Effect read back exactly, objects: `undo` (1 object), `redo` (2), `obj_delete` (only the other cube's id is left), `obj_delete_all` (none), `obj_mirror_x/y/z` (part centres move along that axis only, and instance `mirrored` is true), `obj_split_objects` (2 objects), `obj_split_parts` (1 object of 2 parts), `obj_center` (centre at 125,125 ±1 mm, the middle of the printer's 250 mm bed), `obj_drop` (min z 0 ±0.01), `obj_orient` (z size 20 ±0.5 after a 45° tilt), `obj_instances_up`/`obj_instances_down`/`obj_set_instances` (2/1/3 instances), `obj_instances_to_objects` (3 objects, 1 instance each), `obj_assemble` (1 object of 2 parts), the six `obj_type_*` (sorted part types), `obj_rename` (the typed name), the four `obj_order_by_*` (exact order), the ten `add_handy_*` (exact object names; `add_handy_orca_string_hell` also no dialog open, since its Suggestion question comes only for a process with `only_one_wall_top` on and `min_width_top_surface` above 0, `MenuFactory::load_handy_model()`, and 0.20mm Standard @MyKlipper leaves `only_one_wall_top` off, so the row answers nothing), `import_zip_archive` (1 object), `load_project` (2 objects, project path ends `load_me.3mf`), `new_project` (no objects).
- Effect read back exactly, plates and slicing: `slice_and_preview` (plate 0 sliced and tab `preview`), `slice_all` (2 plates, both sliced), `plate_add` (objects per plate `[2, 0]`), `plate_duplicate` (2 plates, the second holding 2 objects), `plate_delete` (1 plate, objects on `[0, None]`), `plate_rename` (the typed name), `plate_toggle_lock` (`locked` true), `plate_goto` (current 0), `go_to_layer` (top shown layer within 2 of half of `layer_count`).
- Effect read back exactly, app state: `mode_simple/advanced/expert` (`mode`), `go_to_tab` (`tab`), `select_all` (`[0, 1]`), `deselect_all` (`empty`), `filament_add`/`filament_delete` (2/1 slots), the eight camera `view_*` (elevation and azimuth ±2°; `view_top`/`view_bottom` check elevation only), `view_toggle_perspective` (`projection` differs), `start_recording` (recording, path in the output folder), `stop_recording` (no recording, and `stopped.mkv` is non-empty), `toggle_developer_mode` (`developer_mode` flipped), `install_local_plugin` (its copy's name is not in `plugin_list` before the install, which its `before()` reads, and is after), `refresh_plugins` (the side-loaded copy's name is not in `plugin_list` before the refresh, which its `before()` reads, and is after).
- Effect read loosely: the nine `calib_*` (project `name` equals the test's name and at least 1 object), each after OK in its test's dialog. `calib_vfa` answers a second dialog, an information also titled "VFA test" with one OK: Generic PLA @System's maximum volumetric speed, 12.0 mm³/s on this printer, keeps the default end speed of 200 mm/s out of reach at the 0.20 mm layer height, so the dialog's OK lowers the tower's layer height to 0.16 mm and says so (`VfaSpeedFit::ReducedLayerHeight`, `VFA_Test_Dlg::on_start()`). Its row also reads the tower's own `layer_height` as 0.16 (`settings_get {target: object, object: 0, keys: ["layer_height"]}`, source `object`). The other eight dialogs ask nothing more with their defaults on this printer: their other messages are for values out of range and, for Cornering, an end above its warning threshold. The six `add_primitive_<shape>` (1 object whose name contains the shape), `add_primitive_text` (Text gizmo open, 1 object), `obj_fit_volume` (x size > 200 mm), `obj_arrange` (both cubes on some plate), `view_fit_bed` (zoom smaller, `look_at` x within 5 mm of the bed centre, 125), `reset_window_layout` (`sidebar_collapsed` false), `help_benchmark_3d_scene` (more than 1 object, a name containing "Orca", the benchmark window open), `toggle_run_script_panel` (3D view height differs), `help_tip_of_the_day` ("Daily Tips" ImGui window listed).
- File written, existence and size > 0 only: `export_gcode`, `export_stl`, `export_3mf`, `export_drc_single`, `export_toolpaths_obj`, `save_project`, `save_project_as`, `take_screenshot` (the reply's path is in the output folder). File count only: `export_stl_multi`, `export_drc_multi` (2 files each). Archive's G-code entries exactly: `export_sliced_file` (`plate_2` alone), `export_all_sliced_file` (`plate_1`, `plate_2`).
- Window or dialog opened, judged by title substring, then closed: `open_preferences`, `preset_bundle`, `export_config` (cancelled, and the call may error), `help_keyboard_shortcuts`, `help_setup_wizard`, `help_troubleshoot`, `help_network_test`, `help_about`, `help_migrate_filament_presets` (OK pressed), `open_action_replay`, `open_plugins`, `help_check_updates` (any dialog).
- File picker opened once (the auto-answer rule's `uses` == 1) and nothing loaded: `import_file`, `import_configs`, `add_primitive_svg`.
- Refused with an exact code, and no journal step: `send_gcode` (`no_print_host`), `sync_ams` (`no_printer`), `sync_presets` (`not_signed_in`). The Generic Klipper Printer's Print button offers Send G-code through a print host (`MainFrame::available_print_actions()`), and with no host address `Ops::print_route()` refuses it before any dialog: `dialogs()` is empty and `app_state.uploads` is `[]` afterwards.
- Hand-off to another program, only `ran` checked: `help_open_config_folder`, `open_wiki`, `open_youtube`, `install_plugin`.
- Setup: `starts from the Generic Klipper Printer`, `every action has a row`, `every row is an action`, `every action has a call in the fixture`, `Start Recording's folder is the output folder`.

**Not checked:**
- 22 actions never show their effect: the 12 window rows only show that a dialog with that title opened. `help_migrate_filament_presets` presses OK without reading what was migrated. `help_check_updates` answers whatever dialog is topmost, because an empty title matches every dialog. The 3 picker rows never import anything. The 4 hand-off rows never observe the browser or file manager. The 3 refused rows read the code only. `send_gcode`'s refusal is that of a printer with no print host, so neither a host's Send G-code dialog (test_send_gcode uploads to a stub host) nor a Bambu Lab printer's storage dialog, which messages a physical printer and no test opens, is reached here: the storage dialog is the maintainer's to check.
- Written files are never opened, except the two sliced archives (G-code entry names only). A truncated or wrong STL/3MF/DRC/G-code/OBJ, or a blank screenshot, passes.
- Loose effect checks where exact values are known: `calib_*` (only name and object count, and the VFA tower's layer height, not the generated test's objects or the settings each test changes), `add_primitive_*` (substring of the name), `obj_fit_volume` (> 200 mm), `obj_arrange` (on a plate; no positions, no overlap check), `view_fit_bed` (y of `look_at` unchecked), `reset_window_layout` (sidebar only), `toggle_run_script_panel` (any height change).
- The plugin rows read their own copies by name; the other plugins `plugin_list` lists, which earlier tests left, are not read.
- `its action names the fixture's command` compares two static tables. It says nothing about what the action does.

**To settle in review:**
- That a calibration action's journal step has the id alone, not `{"test": "<name>"}`. The action runs its command's person form (`NativeCommands::with_person_form()`), which opens the test's dialog and journals nothing; only `calibration_generate_test`'s own run, with parameters or `silent`, calls `set_journal_args`, and `ActionContext` puts the action's fixed arguments in the step only in place of such a rewrite. Both are this branch's code (`McpToolsProject.cpp`, `McpPersonContext.hpp`, not on `main`). The step with the id alone replays the same, since the action supplies `test`.

**Strength:** Partial — about 70 actions have their effect read back exactly and about 23 loosely; 22 more only open a dialog, hand off, get refused or open a cancelled picker; and 12 export rows mostly check that a file exists. The journal step is pinned exactly for every action.

## `test_menu_items_refusals`
`test_menu_items_refusals.py` · Python, 127 checks

**Tests:** What the object and plate commands built from menu items refuse, called directly and picked from the Speed Dial (Space, search, click). Covers Set as Individual Objects, Select All with a gizmo open, target errors, Rename, Delete on the last solid part and on cut objects, Split, Change Type, Assemble on object-list rows, Mirror, Drop, Add Primitive, Auto-Orient on locked or unprintable objects, and the plate commands on a missing plate. For each case it also checks the state left behind.

**Starts from:** `start(client)`, which "starts from the Generic Klipper Printer" compares with `{printer: "MyKlipper 0.4 nozzle", process: "0.20mm Standard @MyKlipper", filaments: ["Generic PLA @System"]}`. Each scenario then makes a new project and adds what it needs, and the checks read only that project, the notices its picks show and the auto-answer rules it sets, which last one session. A pick clicks the app's own row by its label, `<title> from Orcaslicer`, so an action of a plugin an earlier test left, which names its plugin there, is never picked, and the order the Speed Dial's usage counts give its rows changes nothing a pick reads. The undo fixture keeps its mark in the data folder (`mcp/ops_undo_mark.txt`); the test's first `ops_undo.taken()` call of each check sets it and its result is not read, so a mark another test left counts for nothing.

**Leaves:** an empty project with no auto-answer rules; the Speed Dial's usage counts (`speed_dial.stats` in `OrcaSlicer.conf`) raised for each action it picked, which order the Speed Dial's rows for the tests after it; the undo fixture's mark.

**Decides by:** Exits 1 when any check fails; all checks print at the end, so an uncaught `McpError` from a setup call exits non-zero with nothing printed.
- Start: `starts from the Generic Klipper Printer`, `presets()` as written above.
- Direct refusals: the error text holds a phrase and, where given, the details' `code` is exact (`gizmo_open`, `nothing_selected`, `one_object_only`, `wrong_selection`, `last_solid_part`, `cut_object`, `one_shell`, `auto_drop_question`, `no_such_plate` ×7, `no_objects_to_orient`, `not_printable` ×2, `not_renamed`).
- State after each refusal: `object_list` `total`, names, part ids and types, selection, `mirrored` flags, plate list (`name`, `locked`, `current`) and `rotation_deg`, all compared exactly with the state before.
- Picks: the expected notice text appears in `app_state.notifications`, or an auto-answer rule's `uses` rises by exactly 1 (Rename, last-solid-part message, cut question, Auto-Drop, Edit Plate Name). The state is then read back, for example Assemble on instance rows giving `[("other",1),("Assembly",2)]`.
- Notices two picks share: "Select two or more objects first." (Assemble with one object selected, then Assemble on every part row of an object) and "This acts on one object or part at a time: …" (Split to Objects on two instance rows, then Split to Parts on two part rows). Both refusals' notices are regular ones (`menu_info()` answers them as information), which fade about 10 s after they show, so the first can still be open at the second pick, and while it is open the same text pushed again only moves it to the end of the list (`NotificationManager::activate_existing`). So before the second pick of each pair, the test closes the earlier notice; one that has already faded leaves nothing to close. `widget_list` lists each notification as an `imgui_window` node for its ImGui window, `!!Ntfctn<id>`, with its text as a `text` node in it; the test finds the window whose text holds the notice's text and clicks its large invisible close button, which closes the notification in either theme. That button, labelled " ", and the close glyph beside it have labels the listing cleans to nothing and no `##` name, so `widget_list` lists neither and gives them no ref. The test reaches the invisible one with the locator `{imgui: "", window: "!!Ntfctn<id>", index: N - 1}`, which matches the window's unlabelled items in the order they are recorded; `render_close_button()` submits it last. N is the count the same locator without `index` is refused with ("N ImGui items match …; add \"index\""); it is at least 2, the glyph and the invisible button. A short refusal notice draws no minimize button (`m_multiline` with more than 3 lines only). "the earlier notice is closed" then waits up to 5 s, failing when the time runs out, for `app_state.notifications` to hold no notice with the text. After the second pick, its own check reads the text there again.
- Results that run: `object_delete {}` on two solid parts (the remaining part ids, and the reply's `parts` and `kept`), `object_split keep_z` (2 objects, upper piece above 20 mm), the Auto-Drop "No" pick (pieces dropped below 1 mm), Duplicate Plate (`ops_undo.taken()` count 1, and undo restores 1 plate and 1 object), rename to the same name (no snapshot).

**Not checked:**
- `a pick of Change Type with an object selected says to select a part`: notice text only; the object's part types are not read afterwards.
- `object_auto_orient names only what it turned, not an object on a locked plate`: reads the reply alone. Neither cube's rotation is read, so a turn of the locked-plate cube goes unseen.
- Refusals checked by text only, with no code: `Set as Individual Objects on an object of one instance ...`, `object_delete of an object the project lacks names its index`, `object_mirror with no axis is refused by its schema` (any error containing "axis").
- `and takes no undo snapshot` reads the info-level log through `ops_undo.py`. It would pass if snapshots stopped being logged; the Duplicate Plate count-1 check in the same run would catch that.

**To settle in review:**
- The notices the pairs share are regular notices, not error notices that never fade: `menu_info()` (`McpToolsScene.cpp`, from commits not on `main`) answers `too_few_objects` and `one_object_only` as information, as the menu items told them, since the person can select something else and pick again. So the first notice may fade before the second pick, and the close step then finds nothing; "the earlier notice is closed" still reads the text gone before the second pick, and that pick's own check reads it shown again.
- Reaching the close button through a refusal's count is roundabout. Naming the button in the app (`record_named_item` on the close button in `render_close_button()`) would let the test click it by name; that is a change to the app.

**Strength:** Strong — refusal codes and the state after each refusal are compared exactly, and each pick's notice is its own; only a few picks rest on notice text alone.

## `test_additions_refusals`
`test_additions_refusals.py` · Python, 67 checks

**Tests:** Refusals of the filament, preset, export, import and settings commands. Covers `preset_sync` and `filament_sync_ams` with no account or printer, `view_set` of a layer with no slice, per-object STL and toolpath exports of an empty project (called and picked), a ZIP entry the archive lacks, `layer_height` on a part or a height range, a missing height range, the sidebar while a bare G-code file is open, deleting the only filament slot or one a mixed filament mixes, merging a slot into the mixed filament that mixes it or the mixed filament into a slot, the 64-slot limit, and an `object_order` that leaves an object out. It also checks that a height range's own settings show on its object-list row.

**Starts from:** `start(client)`, which "starts from the Generic Klipper Printer" compares with `{printer: "MyKlipper 0.4 nozzle", process: "0.20mm Standard @MyKlipper", filaments: ["Generic PLA @System"]}`; its one filament slot is the slot "the project has one filament slot" reads. The `preset_sync` refusal needs no account signed in and the `filament_sync_ams` refusals no printer connected, which hold in every data folder the sweep makes: a seeded folder keeps its login in its own token file (`use_encrypted_token_file`), no test signs in, and no test connects to a printer. The ZIP archive is written again on every run (`refusals.zip`, a name only this test uses, in `mcp/filaments_and_files` in the data folder). Its picks click the app's own row by its label, `<title> from Orcaslicer`, as test_menu_items_refusals's do, so a plugin's action never stands in for one.

**Leaves:** a project of two unsaved cubes, `second` and `first`, with 64 filament slots, the last a mixed filament of the first two (the app numbers mixed slots after the physical ones, so the mixed filament made as slot 3 is slot 64 once the slots are added), which the app keeps as its filaments for its next start. It leaves the mixed filament as a person who made it would keep it. There a test that deletes slots down to one with a plain `filament_delete`, which deletes the last physical slot, is refused at three slots: "Filament slot 2 is mixed in the mixed filament of slot 3; delete that mixed filament first." (`mixed_uses_slot`); and the Add Mixed Filament button is hidden at the limit. So the tests after it set their slots with `start()`, which deletes the mixed slot first and leaves no mixed filament. Also `refusals.zip` in the data folder, the handy models' folder as the last folder opened (`recent.last_opened_folder`) and the Speed Dial's usage counts raised for its three picks.

**Decides by:** Exits 1 when any check fails.
- Start: `starts from the Generic Klipper Printer`, `presets()` as written above.
- Refusals: error text holds a phrase and the details' `code` is exact (`not_signed_in`, `no_printer` ×3, `no_layers`, `no_objects` ×2, `no_toolpaths`, `no_such_entry`, `last_filament_slot`, `mixed_uses_slot` ×2, `mixed_filament_slot`, `too_many_filaments`, `order_misses_object`). Some are checked by text only (see below).
- Filament slots: with one slot, `filament_delete {}` is refused as `last_filament_slot` ("only filament slot"). With a second slot and `filament_add_mixed {components: [1, 2], ratios: [50, 50]}`, whose reply names slot 3, three refusals each leave the three slots: `filament_delete {filament_slot: 1}` as `mixed_uses_slot` with "Filament slot 1 is mixed in the mixed filament of slot 3"; `{filament_slot: 1, merge_into: 3}` as `mixed_uses_slot` with "uses this physical filament", the question Merge with asks; and `{filament_slot: 3, merge_into: 1}` as `mixed_filament_slot` with "can be deleted but not merged".
- Details: `entries` == `["cube.stl", "parts/block.stl"]`, and `height_ranges` == the two ranges.
- State left: `gcode_window` and `legend_collapsed` unchanged, export folder empty, `object_list.total` 0, part and range overrides unchanged, `sidebar_collapsed` unchanged, slot count 1/3/64.
- Picks: exact notice text in `notifications` ("The project has no objects.", "No more filament slots can be added.", or containing "The Preview shows no toolpaths"), and `dialogs` == `[]`.
- Height-range row: `widget_list` row shows "has settings" after `wall_loops` is set and not after it is nulled; the selected rows are unchanged.
- Object order: two 20 mm cubes added with `object_add_primitive {name: "first"}` and `{name: "second"}`. "two cubes, first and second" reads `object_list` plate 0's names as `["first", "second"]`. `object_order {plate: 0, order: [1]}` is refused as `order_misses_object`, naming object 0, and "and leaves the order as it was" reads the names as `["first", "second"]`. The control, "a full order is taken": `object_order {plate: 0, order: [1, 0]}` gives the names `["second", "first"]`.

**Not checked:**
- `and leaves the part's settings too` and `and the object's ranges stay` follow refused `settings_get` calls, which only read; they would catch a refused read that changed something.
- Refusals checked by text, with no code: `settings_set`/`settings_get` of `layer_height` on a part, a null `layer_height` on a range, a missing height range, filament settings with `target object`, and the sidebar `view_set`.
- `project_export ... as its action` (no path) checks the refusal only; whether a picker or file appeared is checked only for the folder variant and the picks.

**Strength:** Strong — refusal codes, details and the unchanged state are compared exactly, the order by names that tell the objects apart.

## `test_person_forms`
`test_person_forms.py` · Python, 62 checks

**Tests:** That a call with exactly an action's arguments behaves as a person's pick. `project_save {save_as}` and `project_export {format: gcode}` open their pickers, `project_save` with a path does not, and `preset_export` always opens its dialog. Speed Dial picks of View: Top, Deselect All and Go to layer run in place. `object_arrange`/`object_select {all}` and their `action_run` give the command's reply, journal step and replay, including in the assemble view and with Measure open.

**Starts from:** `start(client)`, which "starts from the Generic Klipper Printer" compares with `{printer: "MyKlipper 0.4 nozzle", process: "0.20mm Standard @MyKlipper", filaments: ["Generic PLA @System"]}`. The three cubes of the arrange and select checks stand at x 60, 128 and 196, y 128, on the printer's 250 mm bed, and the one moved off goes to x -150, where no plate is. One stored value it reads as it finds it: the folder the app remembers for its last export (`app.last_export_path` in `OrcaSlicer.conf`), where the G-code picker starts, which earlier tests set. "nothing was written where the pickers start" lists only the files written there since the test began, so whichever folder an earlier test left, it holds only this test's writes; a folder that no longer exists is left out. Its picks click the app's own row by its label, `<title> from Orcaslicer`, so a plugin's action never stands in for one.

**Leaves:** Recent Projects' `saved.3mf`, in its own temporary folder, which the runner deletes when the test passes; the folder the app remembers for the last file opened (`recent.last_opened_folder`, the handy models' folder); the results of its two replays, `automation/out/replay-<time>/result.json` in the data folder; the Speed Dial's usage counts raised for its picks; and an empty project.

**Decides by:** Exits 1 when any check fails.
- Start: `starts from the Generic Klipper Printer`, `presets()` as written above.
- Pickers: the save/export auto-answer rule's `uses` rises by exactly 1 per call and not for the path save. The file exists for the path save, and no file has an mtime after the start in the project folder or `last_export_path`.
- `preset_export`: `status` `blocked_by_dialog` with a dialog titled "Export Preset Bundle", an error after cancel, the folder empty, and `silent` refused.
- `view_set` bad tab: the error starts with `No tab has the id "no_such_page".` and the payload contains `no_such_tab`.
- Picks: camera elevation ≥ 85, `tab` stays `preview`, the Prepare selection empty, Go to layer's top layer within 1 of the middle, and for each pick no new job under the command's tool name and no notice containing "Started" or "Finished".
